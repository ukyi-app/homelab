# Resource-limit allowlist — check-resource-limits.ts (vector OOM PR #85 포스트모템 + CPU 단일축 편향 해소 가드)
#
# 규칙: 상주 워크로드(Deployment/DaemonSet/StatefulSet)의 main 컨테이너는 cpu·memory request + memory limit
#   필수(cpu limit은 비요구 — throttling 회피). CNPG CR도 스캔한다: Pooler는 pgbouncer 컨테이너,
#   Cluster는 spec.resources를 pseudo-container 'postgres'로 검사(키 형식 Cluster/<name>/postgres).
#   부득이 미설정해야 하면 아래에 한 줄로 등재한다(게이트 면제):
#       <Kind>/<name>/<container>   # 이유   (Cluster는 <container>=postgres)
#   '#' 이후는 주석. 형식 외 라인은 면제 항목이 아니다(문서로만 취급).
#
#   ⚠️ **면제 줄에는 사유가 강제된다**(인라인 `# 사유` 또는 직전 줄 `#` 주석 — 없으면 게이트가 exit 2).
#      형제 둘(check-image-pins.sh:67-83 · check-alert-rules.ts ALLOWLIST)이 이미 갖고 있던 규율인데
#      blast radius가 가장 큰 이 목록에만 없었다(감사 2R critic-C).
#   ⚠️ **강제 면제 건수에는 상한이 있다** — `tools/check-resource-limits.ts`의 `EXEMPT_MAX`(현재 0).
#      정당한 면제를 더하려면 **같은 PR에서** 그 상수를 올려라. 그 diff가 리뷰 지점이다
#      (선례: `scripts/check-bats-accounting.sh`의 `EXCL_MAX`).
#
# ── 강제 면제(enforced exemptions) ──
#   현재 없음 — 로컬 소스 매니페스트의 전 상주 워크로드가 cpu·memory request + memory limit 보유(위반 0).
#   (그래서 EXEMPT_MAX=0이다. 0이라는 상한 자체가 "면제가 늘어났다"의 바닥값이다.)
#
# ── 범위 밖(문서 전용, 게이트 미강제) — 의도적으로 limit 미설정인 알려진 컨테이너 ──
#   이들은 원격-helm 차트/벤더/k3s-시스템이라 소스 매니페스트에 없어 이 게이트가 스캔하지 못한다.
#   강제 대신 "왜 unlimited인가"를 여기 기록해 블라인드스팟을 가시화한다. 변경은 라이브로 확인.
#   ⚠️ **이 두 블록에 수치를 적지 않는다** — 기계가 읽지 않는 산문이라 어떤 게이트도 드리프트를 red로 내지
#      못한다(형식 외 라인 = 문서 전용). 값은 선언 파일·원장을 경로로 가리키고, 여기엔 '어디를 보라'만 남긴다.
#     - tailscale/ts-* tailscale : tailscale operator가 만드는 proxy StatefulSet(런타임 생성 → 소스 매니페스트 부재).
#         proxyclass.yaml(resource-capped)을 defaultProxyClass로 지정해 각 proxy에 memory limit을 cap함
#         (더는 unlimited 아님 — 값은 platform/tailscale/prod/proxyclass.yaml이 SSOT).
#         ProxyClass가 생성하는 StatefulSet이라 이 게이트 스캔 밖 → 원장 tailscale 행에
#         proxy 대수만큼 수기 계상(현재 2대: traefik-ts + pg-rw-tailscale). LB 서비스 증감 시 원장 동반 갱신.
#     - kube-system svclb-* (klipper-lb) : k3s 관리(우리 매니페스트 아님).
#
#   ── 스캔 제외(but limit 보유) — 아래는 unlimited가 아니라 charts/ 하위라 게이트가 못 보는 것뿐 ──
#     local-helm 상주(traefik·argocd·sealed-secrets·tailscale-operator)는 렌더가 charts/(스캔 제외)에 떨어지나
#     각 values(values-traefik.yaml 등)에 memory limit을 선언한다 — 회귀 시 게이트 미포착이라 values 직접 확인.
#     - cnpg-operator manager : 원격 helm 차트라 스캔 밖이나 limit 보유(platform/cnpg/operator/values.yaml의
#         top-level `resources.limits.memory`가 SSOT). ⚠️ 원장 cnpg-operator 행은 manager + cnpg-system/barman-cloud
#         사이드카의 **합**이라 그 단일 값과 같지 않다(memory-ledger.md 2026-09-01 4차). 2026-07-06 이전엔 values가
#         umbrella용 네스팅으로 조용히 무시돼 실제 unlimited였다 — 회귀 시 라이브 deploy resources로 확인.
#     - cert-manager controller/cainjector/webhook : 원격 helm 차트라 스캔 밖이나 limit 보유(2026-06-22 거버넌스 캡으로
#         신설, 2026-09-01 right-size로 재산정). 값의 SSOT는 platform/argocd/root/apps/cert-manager.yaml의
#         helm parameters와 docs/memory-ledger.md cert-manager 행이다 — 여기 수치를 복제하지 않는다.

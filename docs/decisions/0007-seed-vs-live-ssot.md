# 0007 — ArgoCD가 수렴시키지 않는 tracked 값은 자산마다 SSOT를 선언하고, 시드 드리프트는 경고로만 표면화한다

- 상태: 수용(accepted) — 2026-09-03 (감사 2라운드 비평가 추가 결함 3 → 트래커 audit-2026-09 티켓 16 → owner 결정)
- 관련: `CONTEXT.md` 「수렴 클래스」, `platform/adguard/prod/adguardhome.yaml`,
  `platform/adguard/prod/rewrite-reconciler.yaml`, `platform/cnpg/prod/cluster.yaml`

## 맥락

이 레포의 게이트는 "tracked 값이 곧 라이브"라는 전제 위에 서 있다. ArgoCD selfHeal이 라이브를 git으로
되돌리므로 매니페스트를 검사하면 라이브를 검사한 것이 된다. 그런데 그 전제가 성립하지 않는 tracked 값이
있다. **ArgoCD가 수렴시키지 않는 값**이다:

| 클래스 | 예 | 라이브와 갈리는 방식 |
|---|---|---|
| (a) 첫 부팅 시드 ConfigMap | `adguardhome.yaml`의 `AdGuardHome.yaml`(`cp -n` — PVC에 파일이 있으면 무시) | 사람이 AdGuard UI에서 고친 값이 라이브, git은 재구축 초기값 |
| (b) 라이브만 갱신하는 리컨실러의 입력 | `adguardhome.yaml`의 `rewrites:` 블록(리컨실러가 라이브 API로 갱신) | 리컨실러가 라이브를 권위로 삼으므로 git 블록은 첫 부팅 뒤 무의미 |
| (c) 부트스트랩 1회 SQL/스크립트 | `cluster.yaml`의 `postInitApplicationSQL`(initdb 1회) | 기존 클러스터에 no-op — 고쳐도 라이브에 닿지 않는다 |

이 값들은 갈려도 **어떤 신호도 나지 않는다**(감사 2라운드 비평가 추가 결함 3). 어느 finder도 이 축을 열지
않았던 이유는 "무엇과 무엇을 대조할지"가 정해지지 않았기 때문이다 — 그 결정이 이 ADR이다.

## 결정

1. **SSOT는 자산마다 선언한다.** 해당 매니페스트 헤더에 `SSOT: live | git | seed-only` 한 줄을 둔다(문구
   규약 + 리뷰 — check-skeleton류 가드는 세우지 않는다). 선언이 없는 tracked 값은 수렴 자산으로 읽는다.
2. **adguard 본체 설정은 라이브 SSOT + git 시드다.** UI에서 만지는 것이 실사용이라 git→라이브 수렴은
   역행이다. 대신 "시드가 라이브와 다르다"를 **주기 대조 경고**로 낸다 — 리컨실러 CronJob의 형제 스텝이
   시드와 라이브 설정을 비교해 게이지를 push하고 vmalert가 warning을 낸다. red가 아니다: 드리프트는
   결함이 아니라 **재구축 시 되돌아갈 거리**이고, 처방은 시드를 라이브에 맞춰 갱신하는 것이다.
3. **adguard `rewrites:` 블록은 시드 전용이다.** 리컨실러가 이미 라이브를 권위로 삼으므로 git 블록은
   첫 부팅에만 의미가 있다 — 헤더에 그렇게 명시한다(삭제하지 않는 이유: DR 재구축이 리컨실러의 첫
   실행 전에도 이름해석을 해야 한다).
4. **CNPG `postInitApplicationSQL`은 git SSOT이되 재실행되지 않는다.** 변경은 마이그레이션 Job 경로로만
   라이브에 닿는다 — 이 사실을 헤더에 박는다.
5. **범위는 열린 목록이다.** owner도 "사람이 라이브를 고치는 자산"의 전체 목록을 모른다(2026-09-03).
   다음 감사 라운드의 시드↔라이브 축이 finder로 그 목록을 채우고, 자산이 늘 때마다 1의 선언을 붙인다.

## 기각한 대안

**(a) git SSOT 전면** — 드리프트를 red로 보고 git→라이브로 수렴시킨다. 기각: adguard는 UI 편집이
실사용이라 수렴이 운영자가 방금 고친 값을 되돌린다. 게이트가 사람과 싸우면 사람이 게이트를 끈다.

**(b) 관측만** — 문서에 "시드 전용"만 적고 대조를 두지 않는다. 기각: 신호 0인 현재 상태와 같다. 재구축
때 "시드가 얼마나 낡았는지"를 그 순간 처음 알게 된다.

**(c) 헤더 선언을 가드로 강제** — 기각: 값싼 처방 우선. 선언 누락은 리뷰가 잡고, 대조 스텝이 없는
자산은 다음 라운드 finder가 잡는다. 가드는 목록이 닫힌 뒤에 세워도 늦지 않다.

## 결과

- 다음 감사 라운드의 4번째 축(시드↔라이브)을 열 수 있다 — finder의 질문은 "헤더 선언이 없는데
  ArgoCD가 수렴시키지 않는 tracked 값이 있는가"와 "선언은 있는데 대조 스텝이 없는가" 둘이다.
- adguard 대조 스텝(게이지 `adguard_seed_drift` + vmalert warning)은 트래커 티켓 27로 착지한다.
- 이 ADR이 세운 용어(수렴 자산·시드·시드 드리프트)는 `CONTEXT.md`가 소유한다.

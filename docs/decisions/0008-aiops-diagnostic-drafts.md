# 0008 — AIOps의 첫 권한 경계는 장애 진단과 운영 수정 초안까지다

- 상태: 수용(accepted, 설계 결정) — 2026-09-12 사용자 인터뷰 Q1·Q2
- 구현: 설계 중
- 관련: `CONTEXT.md` 「운영 진단 산출물」, ADR-0002, ADR-0007

## 맥락

이 홈랩은 ArgoCD와 기존 변이 워크플로가 배포를 수렴시킨다. 비대화형 Codex를
운영에 도입하는 첫 목적은 장애 알림 이후 원인 파악에 드는 운영자 작업을 줄이는 것이다.
기존 `homelab mcp`는 생성·시크릿 변이까지 노출하므로 진단 전용 인터페이스가 아니다.
PR-first도 일부 동사에서는 자동 머지로 이어져 사람의 검토를 보장하지 않는다.

## 결정

첫 파일럿에서 Codex의 산출 범위는 **장애 진단과 운영 수정 초안**까지다.
사용자는 진단 보고서만 작성하는 안과 허용된 복구를 자동 실행하는 안 사이에서 이를 선택했다.
초안 생성은 실제 운영 변경에 대한 승인이 아니다. 초안의 전달 위치·원격 게시 여부와
구체적인 검증·적용 절차는 후속 설계에서 정한다.

이 경계에서 Codex에 기존 운영 변이 자격을 포괄적으로 넘기는 방식은 맞지 않는다.
후속 구현은 증거 수집·초안 생성에 필요한 접근을 실제로 제한해야 한다.

## 대안과 결과

- **진단 보고서만**: 실행 권한은 좁지만 운영자가 수정안을 다시 만드는 작업이 남는다.
  사용자 선택은 검토 가능한 패치 작성까지 자동화하는 쪽이다.
- **자동 복구까지**: 대응 시간을 더 줄일 수 있으나 잘못된 진단이 운영 변경으로 이어진다.
  첫 파일럿의 범위를 넘어 별도의 권한·검증·승인 결정이 필요하다.
- **진단과 수정 초안**: 원인 분석과 수정안 작성 시간을 줄일 수 있다. 대신 근거가 충분한지,
  초안이 유효한지, 실제 배포로 이어져도 되는지를 구별하는 검토 과정이 남는다.

이 결정은 기존 GitOps 수렴, 자산별 SSOT, owner 전용 신뢰 앵커의 경계를 변경하지 않는다.
무인 운영 변경으로 확대하려면 이 결정과 해당 자산의 기존 ADR을 함께 재검토한다.

## 후속 합의 — 2026-09-12 Q7

운영 수정 초안의 전달은 GitHub PR, 진단 보고는 Telegram을 사용한다.
PR 발행이 산출 범위에 추가됐지만 초안과 운영 적용을 구별하는 권한 경계는 유지한다.

## 후속 합의 — 2026-09-12 Q8

초안의 수정 범위는 진단에 필요한 모든 파일이다. 배포 설정·관측성 규칙으로 한정하는 안은
채택하지 않았다. 워크플로·정책 변경도 제안할 수 있으므로 PR 생성 이후 코드 실행과 자격 공급의
경계를 별도로 설계한다. 수정 제안이 기존 정책이나 ADR을 바꾸면 그 충돌과 채택 여부를 검토에
표시해야 하며, 초안이 기존 결정을 스스로 폐기한 것으로 해석하지 않는다.

## 후속 합의 — 2026-09-12 Q12

첫 파일럿의 수정 대상은 homelab 전체 파일이다. 외부 앱 레포의 소스 변경은 포함하지 않는다.
외부 앱 코드의 수정이 필요한 진단은 근거와 함께 보고하며 homelab 수정으로 해결됐다고 간주하지 않는다.

## 할 일

1. 명세에 "한도 뒤 API 크레딧 자동 사용" 절을 더한다. 넣을 것:
   - 범위: 현재 계정 하나 안에서 구독 ↔ API 방식만 봇이 고른다. 다른 계정으로 바꾸는 일은 owner만 한다.
   - 넘어가는 조건: 구독 실행이 실제 한도 실패로 끝난 뒤에만. 한도 경고, 인증 실패, 과부하, 정책 위반, unknown, 취소, 비상 정지로는 넘어가지 않는다. 분류할 수 없는 구독 오류는 지금처럼 구독 대기다.
   - API가 막혔을 때(결정 3/6): API만 잠그고 운영 알림. API 자동 재시도 없음. 잠금은 owner의 명시적 해제나 키 교체로만 풀린다(구독 성공, 달 바뀜으로 풀리지 않는다). 구독은 리셋 시각 + 1분, 시각을 모르면 30분 간격으로 실제 대기 작업 하나로 확인하고 성공하면 구독으로 잇는다. 빈 큐에 확인용 호출을 만들지 않는다.
   - 세 경로(결정 4/6): 대화, 작업 작성, PR 리뷰, 변경 자체 리뷰가 같은 규칙이다. 구독 한도 경고로 미룬 PR 리뷰는 API를 쓸 수 있는 동안에는 미루지 않는다.
   - 작업 이어가기: 같은 세션·작업 공간에서 새 턴으로 잇는다. 세션 파일이 없거나 unknown이면 스스로 새로 시작하지 않는다.
   - 비용(결정 2/6·6/6): 봇은 실행 수 상한을 두지 않고, Console 잔액과 포함분·결제분의 경계를 알 수 없다. "포함 크레딧만"은 owner의 Console 설정(구매 잔액·자동 충전 없음, 봇 전용 workspace의 지출 한도, 구독 쪽 Usage credits 꺼짐)으로만 지켜진다. 봇 글·알림에 "포함분 사용 중", "청구 0원" 같은 문구를 쓰지 않는다.
   - 알림(결정 5/6): Telegram은 API로 넘어감·구독으로 돌아옴을 한도 구간마다 한 번씩, API 잠김은 바로. 브리핑은 API로 돈 실행 수 한 줄. Discord 운영 경보는 없다.
   - 스위치: 기본 꺼짐. 꺼져 있으면 지금 동작(수동 방식 하나)과 같다.
2. AC를 더한다(조사 AC-A01~A07, A09~A12를 바탕으로. A08 봇 예산 상한은 결정 6/6으로 뺀다). 각 AC에 검증 경계(S1~S5)를 적는다.
3. DECISIONS에 "C38" 절: 결정 여섯과 근거, 버린 안(작업자 자체 재실행, 중앙 표시 전환), 알려진 한계(봇이 포함분 경계를 모름, 구독 ↔ API `--resume` 실호환 미확인). D-14 조건 2·5와 "동료 봇 전환" 7·8의 "봇은 스스로 방식을 바꾸지 않는다"는 지우지 않고, 이 기능이 켜진 범위에서 바뀐다는 한 줄을 덧붙인다.
4. ARCHITECTURE에 계약: 게시 서버가 실행마다 방식을 골라 서명한다, 작업자는 같은 계정의 두 자격 중 지정된 하나만 실행 env에 넣는다, 계정 묶음(이름·revision·지문) 대조, 구/신 판 호환 배포 3단계와 되돌리기 순서.

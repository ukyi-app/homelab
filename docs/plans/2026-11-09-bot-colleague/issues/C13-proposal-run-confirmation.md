## 목표

스위치가 켜져 있을 때 owner가 "작업 목록 보여 줘"라고 말하면 확인 없이 일반 답으로 목록을 받고, "이 저장소에 이런 작업 해 줘"라고 말하면 봇이 이해한 내용을 한 줄로 되묻고 "할게요"·"아니에요" 버튼을 단다. owner가 "할게요"를 누르기 전에는 아무것도 실행되지 않고, 오래되거나 이미 처리된 버튼은 다시 실행되지 않는다. 이 티켓이 만든 동작 표·허용 목록·제안 저장 위에 나머지 동작(C14~C17)이 줄만 더한다. 병합해도 스위치가 꺼져 있으면 운영 동작은 그대로다(제안은 버려지고 버튼이 없다).

## 할 일

1. 동작 표를 만든다: 명세 §4.3 표의 동작마다 종류(읽기 요청, 실행 요청, 작업 질문, 게시 승인, 관리 기능, 없음), 처리기, 허용 대상 대조를 적는 한 곳. 이 티켓은 작업 목록(읽기)과 작업 시작(실행) 두 줄만 연결하고 나머지 줄은 "연결 안 됨"으로 둔다. 관리 기능·구독 끄기·급한 질문 제안은 언제나 버린다.
2. 대화 성공 뒤(C11 자리) 스위치가 켜져 있고 v2 응답에 제안이 있으면 동작 표에 대조한다. 목록에 없거나 연결 안 된 동작, 허용 밖 대상(저장소 정책, 템플릿 카탈로그, 이 대화에서 볼 수 있는 작업)은 버리고 대화 답만 낸다. 스위치가 꺼져 있으면 제안을 보지 않는다.
3. 읽기 요청이면 '/' 처리기와 같은 경로·권한 검사로 바로 실행하고 결과를 일반 답(동료 말투)으로 게시한다.
4. 실행 요청이면 제안을 저장하고(마이그레이션), 한 줄 되묻기 글에 "할게요"·"아니에요" 버튼을 단다. 작업 시작의 내용은 모델이 다시 쓴 글이 아니라 owner 원문(멘션 표기 제거)이고, 모델은 저장소만 고른다. 저장소는 '/' `task`와 같은 정책 대조와 작업 레인 접수 검사를 거친다. 되묻기 글에는 저장소와 원문 앞부분이 보인다. 제안 행의 값은 owner 원문이면 원문 이벤트 참조로 두고, 처리·거절·만료 뒤에는 값 칸을 비우고 digest만 남긴다(C14의 기억 내용이 기억 삭제나 7일 정리 뒤에도 제안 표에 남지 않게).
5. 버튼 검사: 누른 사람이 owner, 제안이 대기 상태, 만료(24시간) 전, 값 digest가 저장값과 같을 때만 실행한다. 처리(실행·거절·만료)한 뒤에는 상호작용 응답으로 그 글의 버튼을 없앤다. 같은 제안을 두 번 눌러도 한 번만 실행된다(제안 행 상태 전이를 한 트랜잭션의 조건부 갱신으로). 실행은 '/' 처리기와 같은 경로를 써서 권한·정책 검사가 같다.
6. 재생 안전: 장애 뒤 복구로 다시 읽은 메시지도 제안만 만들고 실행하지 않는다. 새 메시지가 대기 중인 대화를 대체(`superseded`)하면 그 대화의 제안은 만들지 않는다.
7. custom_id 허용 목록을 표 모양(이름, 칸 수, 처리 분기)으로 바꾸고 기존 네 버튼(`list`, `stop`, `resume`, `cancel`)을 그대로 옮긴 뒤 확인 버튼 두 줄을 더한다. 뒤 티켓은 이 표에 줄만 더한다.
8. outbox 게시 payload에 버튼 줄을 싣는 칸을 더하고 게시자가 그대로 보낸다(대조 표식·멘션 막음 규칙 유지). C15·C17이 같은 칸을 쓴다.
9. 시험: 스위치 꺼짐에서 제안이 있어도 버튼 없음, 버튼 전 실행 0건, 비 owner 거부, 만료·처리됨·digest 변경 거부, 재생 메시지는 제안만, 대체된 대화 제안 없음, 허용 밖 대상·목록 밖 동작 버림, 읽기 요청 즉시 답, 중복 클릭 PostgreSQL 두 연결에서 실행 1번.
10. 기록: 봇 `docs/ai-bot/ARCHITECTURE.md`에 제안·실행 확인 계약 절(동작 표 위치, 제안 표, custom_id 표, 버튼 검사), `docs/ai-bot/DECISIONS.md`에 구현 선택 절, `docs/ai-bot/VERIFICATION.md`에 "C13 제안과 실행 확인" 절, 이 계획 폴더 `README.md`의 C13 상태 줄 갱신.

## 완료 조건

- [ ] 스위치가 켜져 있을 때 작업 시작 제안이 한 줄 되묻기와 버튼 글이 되고, 버튼을 누르기 전 실행 0건이다.
- [ ] owner가 아닌 사람, 만료(24시간)·처리됨·값이 바뀐 제안의 버튼은 거부되고, 처리된 글의 버튼은 사라진다.
- [ ] 같은 버튼을 두 번 눌러도 작업이 한 번만 시작된다(PostgreSQL 두 연결).
- [ ] 기록에서 재생된 메시지는 제안만 만들고, 목록에 없는 동작이나 허용 밖 대상의 제안은 버려지고 대화 답만 나간다.
- [ ] 작업 목록 제안은 확인 없이 '/' `list`와 같은 권한 검사로 실행돼 일반 답으로 달린다.
- [ ] 스위치가 꺼져 있으면 제안이 있어도 버튼이 없다.

## 목표

`01` §4: Discord 대화, 영속 작업 저장소, 읽기 전용 홈랩 조회 (R01~R07)를 로컬 코드와 `mock`·`local_integration` 시험으로 만든다. 실제 Discord·플랫폼 연동과 첫 배포는 T16b다.

## 나눈 이유

V1 범위 조정 안 3(확정(사용자 2026-10-18, T15))으로 옛 T16을 둘로 나눴다. 공유 계약은 플랫폼과 무관해 T13 전에 만들 수 있다. 대가는 둘이다. T13 실측이 계약을 바꾸면 T16b에서 고칠 일이 생긴다. 실연동 완료를 주장하지 않도록 증거 등급을 엄격히 나눠야 한다(봇 저장소 `docs/ai-bot/V1_PLAN.md` §4).

## 할 일

1. T15에서 `blocked`로 남긴 플랫폼 실측 항목은 플랫폼이 있어야 해서 T16b 시작 때 다시 확인한다. 이 티켓은 그 결과를 기다리지 않는다.
2. 이벤트·작업·outbox 스키마와 게시 계층을 만든다. 이 공유 계약은 이 티켓이 소유하고, T17·T18·T20은 추가 변경만 한다.
3. `01` §4의 입력·허용·금지·완료·실패 계약을 코드와 시험에 반영한다.
4. Discord 어댑터를 D-17 기본값으로 만들고 모의 Gateway·REST로 시험한다.
   - `MESSAGE_CONTENT` 특권 intent를 켠 동작이 기본이다. 끈 경우의 명령/버튼 모드도 R01대로 만든다.
   - 허용 채널에서 멘션이나 `/` 명령으로 공개 스레드를 시작하고, 스레드 안 후속 메시지는 멘션 없이 처리한다. `auto_archive_duration`은 1440분이다.
   - 허용 사용자는 owner 1명이다. 채널은 둘이다(대화, 알림·리뷰·브리핑).
   - 모든 봇 메시지에 `allowed_mentions`의 `parse` 빈 목록을 준다.
   - 서버·채널·사용자 ID는 키 이름으로만 읽는다. 실제 값은 Infisical `/apps/homelab-bot/`에만 둔다(D-13, D-17).
5. 작업자 계약(D-14, D-15)을 정하고 모의 작업자로 시험한다.
   - 게시 서버는 작업자 Service의 포트 8080으로 작업을 보낸다. 게시 서버의 앱 포트(webhook 수신)는 8080, 경보 수신 포트는 8081이다.
   - 작업 레인은 동시성 1이다.
   - 작업자에는 GitHub 자격이 없다. 코드는 `codeload.github.com` 압축본으로만 받는다. 받은 코드는 작업자가 `git init`으로 한 번 커밋해 `codex exec`의 Git 저장소 요구를 맞추고, diff는 base·head 압축본으로 만든다. push와 PR 생성은 게시 서버가 D-24 App으로 한다(T19).
   - 모델 한도 도달·인증 만료 때는 다른 계정·인증으로 자동 전환하지 않고 대기 상태로 둔다(`00` §7 7항).
6. 대화 레인의 호출 경로와 동시성을 정한다. 출발점은 봇 저장소 `ARCHITECTURE.md` 초안의 제안이다 [초안 인용: ARCHITECTURE §1·§2·§9]: 대화 레인도 작업자에서 `codex exec`를 쓰고(방안 1. 게시 서버가 대화 모델을 직접 부르는 방안 2는 대안), 작업자 모델 호출 동시성은 대화·작업 레인을 합쳐 1이다(D-14 조건 3). 대화 레인 지연과 직렬 대기 시간의 측정 계획(모의는 이 티켓, 실측은 T16b)과 함께 이 제안을 확정하거나 바꾸고 `ARCHITECTURE.md`에 적는다. 레인을 파드로 나눌지는 T18이 판단한다(ARCHITECTURE §5.1 열린 항목).
7. 읽기 어댑터(R05~R06)는 사전 승인 질의 템플릿만 보낸다. Grafana OSS Viewer가 모든 데이터소스를 질의할 수 있어 로그 제외를 플랫폼 권한으로 세울 수 없기 때문이다(T15 조사). 템플릿마다 데이터소스, 네임스페이스, 시간창 상한, 응답량 상한을 둔다. 보존 기간(메트릭 30일, 로그 14일, 설계 C.3.7)은 시간창 상한이 아니다.
8. 봇 중단 경보 연결(OPS-02)은 `ARCHITECTURE.md` §8 제안(내부 건강 상태를 readiness에 묶기, 봇 전용 healthchecks.io 하트비트)을 로컬에서 만든다. 실제 체크와 경보 확인은 T16b다.
9. DM 허용 여부와 브리핑 시각(R18)을 사용자에게 묻고 정한다. D-17에서 미정으로 남긴 두 값이다. 정하기 전에는 설정 초안에 `null`로 둔다(`00` §8).
10. `04` §4 시험을 `mock`·`local_integration`으로 실행하고 결과를 기록한다. 실연동이 필요한 부분은 `blocked`(사유: 실연동 전, 해소: T16b)로 적는다.

## 제약

- 실제 Discord, GitHub, 플랫폼, 모델 호출을 쓰지 않는다. 계정 생성, App 설치, 게시, 배포를 하지 않는다(`00` §7 8항).
- `mock`과 `local_integration`을 실연동 결과로 쓰지 않는다(`04` §3).
- 봇 저장소 `ukyi-app/homelab-bot`은 public이다. 시크릿 값, 실제 Discord·GitHub 숫자 ID, 운영 산출물을 넣지 않는다(D-13, D-29).
- 개인 `~/.codex*`를 읽거나 복사하지 않는다(D-14).

## 완료 조건

- `04` §4 시험 AUTH-01·02, EVENT-01~04, CHAT-01·02, READ-01·02, SEC-01, OPS-01·02의 `mock`·`local_integration` 결과가 기록돼 있다 (spec §7 AC-B3).
- spec §7 "단계 AC 공통 완료 규칙"을 따른다. 배정된 시험에 `fail`이 없다. `blocked`·`not_run`은 사유와 해소 티켓을 함께 적는다. 이 단계의 보안 경계 시험(AUTH-01, READ-02, SEC-01)은 이 경로에서 최소 `mock` 또는 `local_integration`으로 `pass`다.
- DM 허용 여부와 브리핑 시각이 정해져 있다.
- 대화 레인의 호출 경로와 동시성이 D-14 조건에 맞춰 지연·직렬 대기 측정 계획과 함께 `ARCHITECTURE.md`에 적혀 있다.
- 코드와 문서 변경이 봇 저장소 PR로 들어가 있다(main은 `app-main`으로 보호돼 PR로만 들어간다. 병합은 사람 승인 뒤).
- HANDOFF가 있다.

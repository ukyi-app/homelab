# T13 테스트 앱 통합 검증

- 단계: P2 플랫폼 구축 (플랫폼 통합 검증 담당)
- 상태: 대기
- 명세: [../spec.md](../spec.md) §9
- Blocked by: T08, T10, T11, T12
- 선행 결정: D-12 (빈 NUC 검증 방식), D-08 (확정(사용자 2026-10-18): 시나리오 14 추가 확인), D-29 (확정(사용자 2026-10-18): 시험 앱 저장소도 public)
- 연결 AC: AC-P5~AC-P13
- 수행: 에이전트 + 사람

## 목표

테스트 앱 하나로 플랫폼 프롬프트 §9 시나리오 전체(1~17)를 실행해 플랫폼을 판정한다.

## 할 일

1. 시나리오 1~17을 실행하고 각각 `실제 검증 완료 / 설계상 기대 / 실패`로 기록한다.
2. 시나리오 13(빈 환경 재구축)은 D-12 방식(추천: VM)으로 실행한다.
3. 실패와 미실행 항목마다 후속 티켓을 만들거나 한계로 명시한다.
4. 봇을 위한 여지(AC-P12 다섯 자리, 리뷰 전용 App 저장소별 설치 포함)의 경로·계정·설치 가능 여부를 실제로 확인한다. 다섯 자리는 명세 §4.4에 있다.
5. 배포 갱신 주체가 아닌 신원의 digest PR이 자동 병합되지 않는지 확인한다 (AC-P8).
6. 시나리오 14에 D-08 추가 확인을 넣는다: 셀룰러 Tailscale 기기(AdGuard 정지 중 광고 도메인 차단, 일반 도메인 정상), 사용자 규칙 적용률(AdGuard Home 전용 시험 차단 규칙을 집 Wi-Fi·셀룰러에서 20회씩. 공용 DNS에서 정상 주소가 나오는 시험 이름을 쓰고 `0.0.0.0` 응답만 센다, 설계 G 시나리오 14). 측정값을 결과표에 남긴다.

## 완료 조건

- 시나리오 1~17이 모두 `실제 검증 완료`이거나, 사용자가 승인한 한계로 기록돼 있다.
- 필수 시나리오에 실패나 미실행이 남아 있으면 T13은 완료가 아니다. 수정 티켓을 만들고, 수정 뒤 해당 시나리오를 다시 실행한다. T16·T22는 T13이 완료돼야 시작한다.

## 검증

결과표의 각 줄에 실행 명령, 시각, 증거 위치가 있다. 결과표는 설계 문서 G절 옆에 두고 PR로 main에 병합한다(명세 AC-X1). 공개되면 안 되는 증거는 저장소 밖에 두고 위치만 적는다.

# 올리브 계획 (2026-11-13)

지금의 `homelab-bot`을 올리브로 전면 교체하는 계획이다. 올리브는 hc(herdr-core) 위에서 오래 사는 얇은 오케스트레이터와 일마다 띄우는 하위 에이전트로, 운영 중 문제가 생기면 스스로 원인을 찾아 PR을 올리고 병합은 관리자가 한다.

## 지금 상태

- 계획 초안. 2026-11-13에 관리자와 세부를 정했다(`spec.md` §5.1 D-01~D-47, 2026-11-14에 대화 방식, 진단 과정, 감독과 hc의 자리, 비상 정지, 계정 전환의 세부를 이어서 정했다. 2026-11-16에 남은 미정 넷을 정했다: 닫힌 후보 PR의 글, 템플릿과 `homelab-bot-ops`의 제외, 새 코드 저장소의 이름 `ukyi-app/olive`, 2주 시범 운영. 같은 날 O07 결과를 보고 코드 작성 작업자 코드를 옮길 시점(D-46)을, O02 결과와 그 뒤 실측·검토를 보고 본체 격리(D-47: 같은 파드 안에서 본체를 다른 uid 컨테이너로 분리)를 정했다. D-47은 2026-11-17에 O25 실측을 보고 관리자가 확정했다). 구현 대기.
- 옛 봇은 꺼져 있다(O01: 게시 서버 homelab #1281, 작업자 둘 #1282). 만드는 동안 Discord 봇은 없고 경보는 Telegram으로 온다.
- 옛 봇의 멈춘 작업(C40~C47, 봇 PR #155)은 보류 중이다. O07이 코드를 읽고 가져갈 것과 버릴 것을 나눴다(2026-11-16, `issues/O07-old-bot-triage.md`의 "결과"). 관리자가 PR #155를 병합 없이 닫기로 했고(2026-11-16, 브랜치는 남김), 쓸 부분은 O09·O17이 `olive`로 복사한다.
- 검증 티켓의 상태(2026-11-16, 각 티켓의 "결과"):
  - O03: 돌려 본 다섯 경우 완료. 구독 ↔ 구독의 이어 열기는 조건부 됨(앞 계정의 thinking은 넘어가지 않는다). `claude-work` → `claude-sub` 쌍과 장기 토큰은 대기.
  - O04: 완료. 구독 주간 한도, 틀린 키 401, API workspace 지출 한도(400, `claude -p`와 OpenCode)를 봤다. OpenCode의 지출 한도 신호는 `response.body`의 문구 접두어로 결정적으로 읽을 수 있어 B-08의 "막히면"은 생기지 않았다. 크레딧 소진·402·API의 429는 못 봐서 미상으로 다룬다.
  - O06: 읽기 확인 완료(Discord 독자는 관리자 답으로 확인). 4-1 A·B 쓰기 시험 완료(2026-11-17, `homelab-smoke`): 좁힌 설치 토큰이 되고, workflows 권한 없는 writer는 워크플로 파일을 Git push로도 REST로도 올리지 못했다. 다른 저장소 배제는 못 봤다. writer 설치는 `homelab-smoke` 하나로 본다(설치의 마지막 변경 시각으로 간접 확인, 목록 자체는 직접 읽지 못함). 빈틈 둘: 봇 저장소 main에 필수 검사가 없고(O15에서 ruleset으로 건다, 관리자 결정 2026-11-16), 비공개 저장소에 보호 규칙이 없다(저녁 재확인에서 조직은 Team, ruleset 0개). 4-1의 C·C-PR·D(임시 ruleset)는 하지 않았고, 할지와 범위는 관리자가 A·B 결과를 보고 정한다(아직 정하지 않았다).
  - O02: 운영 클러스터 시험 완료(hc 0.1.21). core·holder·분리된 후손이 모두 세션 파드 cgroup 안이었고 파드를 지우자 비었다. 그래서 B-02(파드)는 유지한다. 같은 컨테이너의 모델·도구는 hc 소켓·상태·다른 프로세스의 환경에 닿는다. 그래서 관리자가 D-47로 본체(모델, MCP 연결부, 훅)를 hc와 다른 uid·다른 컨테이너로 분리하기로 정했고, 도구 정책은 보조다. 시험 파드는 껐고(#1293) 차트와 도구를 치우는 PR(#1294)만 남았다.
  - O25: 완료(2026-11-17). 1차 시험(2026-11-16, 운영 k3s `v1.36.6+k3s1`)에서 전체 재시작이 옛 본체를 모두 끝낸 뒤 init부터 돌았고, 거짓 종료·중계만 끊기·실행기만 죽이기·규칙 누락에서 옛 본체 생존 중 새 자격은 0회, 본체에서 hc 소켓 직접 연결은 거부, 규칙이 빠지면 시작이 거부됐다. 2차 시험(2026-11-17, 셸 변형과 Claude 변형)에서 자격 흔적 검사가 `됨`(1차는 `kubectl exec` 진입 프로세스의 AppArmor 라벨 차이로 `판단 필요`), 본체 컨테이너만 재시작이 `됨`, 실제 Claude Code 2.1.325가 중계를 거쳐 `4.claude.대화형 됨`이었다. (4)의 끝내기는 관리자 결정(2026-11-16)대로 종료 요청으로 판정했고(SIGTERM 뒤 234ms) 앱의 끝내기 키는 `안 됨`으로 남았다. 관리자가 2026-11-17에 D-47을 확정했다. 알린 한계 넷((4)의 끝내기, (5)의 증거는 1차 한 번, 노드 판정은 셸 본체로만, 로그인 뒤 Claude 동작과 제품 통계는 재지 않음)은 O09·O10이 이어받고, 로그인 뒤 동작은 O10에서 잰다. 시험 파드는 껐고(#1314) 시험 차트와 도구는 스위치를 끈 채 남아 있다. 치울지는 미정이다. 2026-11-16에 Claude Code의 버전 갱신(D-48: 버전·sha256 고정과 자동 PR, 자체 업데이터 끔)과 텔레메트리(D-49: 제품 통계만)도 정했다.
  - O05: 완료. 두 계정 모두 `claude -p`와 OpenCode의 사용이 포함 크레딧에서 차감됐고 다른 잔액과 구독 사용률은 그대로였다(관리자 화면 확인). 다음 지급 때의 동작은 못 봤다. O04·O05가 끝나 D-15의 "검증 전에는 `claude-work`부터" 조건은 찼고, 크레딧 후보를 실제로 켜는 것은 O17이다.
- 디스크(O23): 런북이 병합됐고(homelab #1284) 2026-11-16에 관리자가 청소를 한 번 실행했다(243.1GiB 회수, 루트 사용 541GiB → 298GiB). 폴더 크기 지표, 미리 알리기, 스킬 갱신은 대기.
- 아직 안 정한 것은 `spec.md` §5.2(기본값, 관리자 미확정)와 §5.3(미정)에 있다. 검증 티켓(O02~O06)의 남은 결과와 O25가 O10에 넘긴 측정(로그인 뒤 Claude 동작)이 설계를 바꿀 수 있다.

## 목표

지금 게시 서버를 올리브의 현관으로 바꾼다. '/' 명령이 없고, 단순 조회는 모델 없이 답하고, 모든 발송 경로가 하나의 공개 검사를 거친다. 현관은 오케스트레이터에 좁은 API만 연다.

## 할 일

1. '/' 명령 등록 제거: Discord 등록 목록에서 지우고 동기화한다(F-7). 내부 처리기는 O07 표대로 남기거나 지운다.
2. 말로 받는 입구: 관리자·서버·채널·대화 소유자를 먼저 검사한 뒤에만 오케스트레이터로 넘긴다. 다른 사람의 글, webhook, 인용·전달 메시지는 관리자 요청으로 보지 않는다.
3. 모델 없는 조회: 뜻이 분명한 한국어 표현(살아 있는지, 배포 상태, 진행 중 작업)을 허용된 조회 템플릿·저장 상태에 연결한다. 모호하면 오케스트레이터로 넘긴다. 내부 템플릿 ID 대신 공개 표시명(F-6).
4. Discord 관리 요청 거절: 계정 전환·등록·삭제, 비상 정지 걸기·해제(D-21), 권한 변경 요청에는 고정 안내("`homelab` CLI에서 해 주세요")만 답한다. 모델에 넘기지 않는다.
5. 발송 한 길: 답, 진행 알림, 오류, 확인 카드, 브리핑, "오늘 배운 것", hc·하위 작업 완료 알림, PR 본문·리뷰·인라인 댓글, embed 필드, 링크, 첨부 이름이 모두 최종 payload를 만드는 같은 함수와 `scanPublicText` 계열 검사를 거친다. 검사 결과를 payload digest·정책 revision·목적지에 묶는다. `safe_summary` 라벨만으로 통과시키지 않는다.
6. F-1~F-8을 하나씩 닫는다:
   - F-1 PR 리뷰: 최종 본문·인라인 댓글·경로까지 검사.
   - F-2 브리핑 기억: 기억 항목과 최종 브리핑을 최신 정책으로 다시 검사.
   - F-3 외부 세션 완료: 공통 검사 + 원시 세션 ID 대신 별칭.
   - F-4 내부 식별자: 모델 입력 최소화, 공개 별칭.
   - F-5 고정 안내: 필요한 상태·다음 행동만.
   - F-6 읽기 템플릿 ID: 공개 표시명.
   - F-7 '/' 등록: 1번.
   - F-8 GitHub 추적 메타데이터: 공개 검토에 필요한 revision만, 내부 ID는 비공개 감사로.
7. 확인 카드(D-26, D-30, `spec.md` §11.2): 버튼을 달지 않는다. 승인은 메시지 전체가 정해진 낱말("올려", "취소")일 때만 받고, 현관의 코드가 글자를 대조한다(모델을 거치지 않고, 오케스트레이터로 넘기기 전에 가로챈다). 대기 카드가 하나인 스레드에서는 그냥 쓴 낱말을, 둘 이상이면 카드에 단 답장만 받는다. 옛 봇의 버튼 처리(`pressProposal`)의 검사(쓴 사람, 대기, 만료, digest, 한 번만)를 같은 함수로 태운다. 승인 낱말을 쓸 수 있는 시간 24시간, 승인한 뒤 10분 안에 실행, 내용·대상·보호 경로가 바뀌면 즉시 무효. 처리·만료된 카드는 그 자리의 글을 고쳐 상태를 보인다. 옛 버튼(실행 확인, 게시 승인, 질문 선택)은 O07 표에서 버림으로 가른다.
7-1. 선택지(D-29): 올리브가 번호를 붙여 글로 묻고 관리자가 말로 답한다. 이것은 승인이 아니라 대화라서 오케스트레이터가 읽는다.
8. 오케스트레이터용 좁은 API: `request_reply`, `request_approval`, `request_publication`, `read_observation`(모델 없는 조회 재사용) 같은 고정 동작만. 목적지·동작은 서버 정책이 정한다.
9. 민감한 상태 답을 보낼 곳은 O06 결과대로.
10. 다시 읽기(D-22): 관리자가 지난 대화를 다시 보라고 말할 때만 Discord의 그 스레드를 다시 읽어 새 입력으로 넘긴다(그때부터 168시간). 모델이 부르는 도구로 열지 않는다. 관리자가 지운 글은 읽을 수 없다.
11. 자기 저장소 요청(D-25): 올리브에게 `homelab-bot`·`olive`를 고쳐 달라는 요청은 진단 답으로만 이어진다. writer는 그 두 저장소를 대상으로 받지 않는다(O15).
12. 다시 켤 때(AC-02): 현관은 2026-11-13부터 멈춰 있어 원문 7일 정리가 밀려 있다. 옛 봇의 정리는 기동 때와 1시간마다 돌지만 [확인] 끝나지 않은 작업, 누락 복구 대기, 확정 전 게시의 원문은 고르지 않는다(`spec.md` §9.1.1). 그래서 다시 켜기 전에 멈추기 전부터 남아 있던 그 세 가지를 종결 처리한다(끌 때 진행 중 작업은 없었다. 누락 복구 대기와 확정 전 게시는 버린다). 멈춘 동안 온 Discord 메시지는 받아 오지 않는다(누락 복구가 원문을 새로 쌓지 않게 한다. 관리자가 필요하면 다시 말한다). 그 뒤 첫 기동의 정리가 끝나면 7일이 지난 원문이 남았는지 세고, 남은 것이 있으면 어느 칸의 몇 건인지와 이유를 적어 관리자에게 알린다. 예외를 없애고 정리를 별도 작업으로 옮기는 것은 O18이다. `core.yaml`의 `bot-slot` 제외를 같은 배포에서 지운다.

## 완료 조건

- [ ] Discord '/' 명령 목록이 비어 있다(AC-04).
- [ ] 단순 조회가 모델 호출 0번으로 답한다(AC-05).
- [ ] F-1~F-8 각 경로에 심은 가짜 비밀이 고정 안내로 바뀐다(AC-06).
- [ ] Discord의 관리 요청이 CLI 안내로 거절된다.
- [ ] 현관을 다시 켜기 전에 옛 끝나지 않은 작업·누락 복구 대기·확정 전 게시가 종결됐고, 첫 기동의 정리 뒤 7일이 지난 원문이 0건이다. 0건이 아니면 칸별 건수와 이유를 관리자가 받아들인 기록이 있다(AC-02).

## 할 일

1. 역할별 순서(§8.3 표)를 선택기에 넣는다. 오케스트레이터 후보 목록에는 포함 API 크레딧이 없고, 하위 에이전트 후보 목록은 포함 API 크레딧이 맨 앞이다(D-15). O04·O05 결과가 나오기 전에는 하위 에이전트의 크레딧 후보를 꺼 둔다(설정값 하나로 켠다).
2. 판정표: O04 실측으로 신호 → 처리(넘어감/대기/잠금/미상). 버전을 고정하고 비식별 샘플로 시험 고정값을 만든다.
3. 전환 장부: 계정별 구독 상태(쓸 수 있음, 한도(리셋 시각), 인증 막힘), API 상태(쓸 수 있음, 그달 소진(다음 확인 시각), 잠김), 실행마다 고정된 계정·방식·runId. 소진과 잠김을 따로 적는다. 소진은 새 크레딧이 들어온 뒤(구독 결제 주기 기준, 계정마다 다음 지급 예정일을 장부에 둔다) 자동으로 다시 확인하고, 잠김은 관리자가 CLI로 풀 때까지 그대로다(D-16). 감독 재시작 뒤에도 복원.
4. 넘어가기(§8.2): 한 번의 전이, 옛 프로세스 종료 확인 뒤 새 자격으로(O03 결과대로 resume 또는 인계). 작업자 env에는 그 실행의 자격 하나만.
5. 크레딧 단계의 실행 도구: 하위 에이전트는 OpenCode(D-14), 도구 없는 격리 읽기만 `claude -p`(B-08). O04·O05 결과가 OpenCode를 막으면 B-08의 "막히면"대로 관리자에게 묻는다. 구독 로그인을 제3자 도구에 넣지 않는다.
6. 크레딧 소진과 API 막힘(§8.2 5번, D-16): 크레딧 후보는 둘이다(`claude-sub` 것 → `claude` 것, 계정마다 Console API 키 하나). 그달 크레딧 소진은 평소 일이라 다음 후보로 넘어가고, 둘 다 떨어져 `claude-work`로 갈 때 한 번 알린다. 다음 달 경계 뒤 실제 작업 하나로 복귀를 확인한다. 결제 오류·인증 실패는 API만 잠그고 Telegram 알림, 해제는 CLI. 소진과 막힘을 신호로 가르지 못하면 잠금으로 본다.
7. 복귀: 리셋 + 1분(모르면 30분)에 실제 대기 작업 하나로 확인. 빈 확인 호출 없음.
8. `homelab` CLI: 올리브 계정 목록·상태, 수동 전환(다음 안전 경계부터), 등록·삭제, API 잠금 해제. 출력은 짧은 요약, 상세는 `--verbose`.
9. Discord: 전환 요청은 현관이 CLI 안내로 거절(O08). Discord에는 자리 비움만, 계정명·만료·세션 ID 없음. "포함분 사용 중", "청구 0원" 같은 문구를 쓰지 않는다.
10. 알림: 넘어감·돌아옴은 한도 구간마다 Telegram 한 번씩, API 잠김은 바로.

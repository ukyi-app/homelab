한도에 걸리면 감독이 D-09 순서로 다음 계정·방식으로 넘어가고, 풀리면 앞 계정으로 돌아온다. 관리자는 `homelab` CLI로 수동 전환·등록·삭제·잠금 해제를 한다.

## 할 일

1. 역할별 순서(§8.3 표)를 선택기에 넣는다. 오케스트레이터 후보 목록에는 포함 API 크레딧이 없고, 하위 에이전트 후보 목록은 포함 API 크레딧이 맨 앞이다(D-15). O04·O05 결과가 나오기 전에는 하위 에이전트의 크레딧 후보를 꺼 둔다(설정값 하나로 켠다).
2. 판정표(`accounts.md` §2): O04 실측으로 신호 → 처리(넘어감/대기/잠금/미상 보류). 버전을 고정하고 비식별 샘플로 시험 고정값을 만든다. `system/api_retry`와 도구 안의 재시도는 최종 실패가 아니다. 모르는 400과 세부 원인 없는 429는 미상이다.
3. 전환 장부(`accounts.md` §4, 감독 장부의 일부): 계정별 구독 상태(쓸 수 있음, 한도(리셋 시각), 잠김(인증 실패, D-40), 대기(접근 정책·결제)), API 상태(쓸 수 있음, 소진, 잠김, 미상 보류), 계정별 다음 지급 예정일(값·정밀도·출처·확인한 날. "소진 월" 칸은 두지 않는다), 구독 토큰의 발급일과 만료일(확인·추정), 수동 선택과 그 끝 시각(D-41), 실행마다 고정된 계정·방식·runId. 소진과 잠김을 따로 적는다. 소진은 다음 지급 예정일 뒤 자동으로 다시 확인하고, 잠김은 관리자가 CLI로 풀 때까지 그대로다(D-16, D-40). 감독 재시작 뒤에도 복원하고, 재시작·자격 교체·예정일 경과가 잠금을 풀지 않는다.
4. 넘어가기(§8.2, `accounts.md` §5): 한 번의 전이, 옛 프로세스 종료 확인 뒤 새 자격으로(O03 결과대로 resume 또는 인계). 헤드리스는 SIGINT를 먼저 보내고 `CLAUDE_CODE_RESUME_INTERRUPTED_TURN`을 실행 환경에서 막는다. 실행에는 그 실행의 자격 하나만 준다: 오케스트레이터는 세션 실행기가 계정 세대마다 새 hc core를 띄워 그 core의 환경에만, 작업자는 역할별 실행기가 hc 없이 허용 목록으로 만든 환경에만(D-37, `accounts.md` §6.3).
5. 크레딧 단계의 실행 도구: 하위 에이전트는 OpenCode(D-14), 도구 없는 격리 읽기만 `claude -p`(B-08). O04·O05 결과가 OpenCode를 막으면 B-08의 "막히면"대로 관리자에게 묻는다. 구독 로그인을 제3자 도구에 넣지 않는다.
6. 소진, 막힘, 못 가른 오류(§8.2 5번):
   - 크레딧 후보는 둘이다(`claude-sub` 것 → `claude` 것, 계정마다 Console API 키 하나). 이번 주기의 크레딧 소진은 평소 일이라 다음 후보로 넘어가고, 둘 다 떨어져 `claude-work`로 갈 때 한 번 알린다. 그 계정의 다음 지급 예정일 뒤(달력의 1일이 아니다) 실제 작업 하나로 복귀를 확인한다(D-16).
   - API 결제 오류·키 인증 실패는 그 계정의 API만 잠그고 Telegram 알림, 해제는 CLI(D-16).
   - 구독 토큰 인증 실패(`authentication_failed`)는 그 구독만 잠그고 정한 순서의 다음 후보로 넘어가며 Telegram으로 바로 알린다. 해제는 CLI. `oauth_org_not_allowed`·`account_on_hold` 같은 접근 정책 거절은 넘어가지 않고 기다리며 알린다. 구독 토큰 만료 30일 전부터 하루 한 번 오는 글로 미리 알린다(D-40).
   - 소진인지 결제 장애인지 가르지 못한 API 오류는 잠그지 않고 "미상 보류"로 두고 다음 후보로 넘어간다. 하루 한 번과 그 계정의 다음 지급 예정일 뒤에 실제 작업으로 다시 확인하고 한 번 알린다. CLI로 앞당길 수 있다(B-17).
   - 지출 상한에 닿으면 그 계정·그 한도 범위만 기다리고 다음 후보를 쓴다. 지급이 예정일보다 늦으면 일이 있을 때 30분 간격으로 확인하고, 24시간이 지나도 안 들어오면 한 번 알린다(B-17).
7. 복귀(`accounts.md` §3): 리셋 + 1분(모르면 30분)에 실제 대기 작업 하나로 확인. 빈 확인 호출 없음. 복귀는 타이머가 아니라 실제 일의 성공으로 확정한다. 작업자는 지금 일을 마친 뒤 다음 일부터, 오케스트레이터는 턴 경계에서 앞 후보로 간다.
8. `homelab` CLI(`accounts.md` §7): 올리브 계정 목록·상태, 등록·삭제, 구독·API 잠금 해제, 미상 보류 재확인, 다음 지급 예정일 등록. 수동 전환은 다음 안전 경계부터 정한 시간까지다. 기본 24시간이고 `--for`로 줄이거나 늘리며, 지나면 자동 순서로 돌아간다. `account auto`로 바로 되돌린다. 기한 없는 고정은 만들지 않는다. 남은 시간은 `account list`에 보인다. 고른 계정이 한도에 걸리면 자동 순서로 넘어가며 알린다(D-41). 쓰는 중인 계정을 지우면 새 실행을 바로 막고 지금 실행이 끝난 뒤 지운다(B-17). 출력은 짧은 요약, 상세는 `--verbose`.
9. Discord: 전환 요청은 현관이 CLI 안내로 거절(O08). Discord에는 자리 비움만, 계정명·만료·세션 ID 없음. 하루 한 번 오는 글에는 "수동 선택 중"(D-41)과 "구독 토큰 만료가 30일 안"(D-40)이라는 사실만 싣고 계정명·날짜는 CLI에서 보게 한다. "포함분 사용 중", "청구 0원" 같은 문구를 쓰지 않는다. "이번 달", "다음 달" 대신 "이번 주기", "다음 지급 예정일 뒤"로 쓴다.
10. 알림(`accounts.md` §8): 넘어감·돌아옴은 한도 구간마다 Telegram 한 번씩, API 잠김·구독 잠김·접근 정책 거절은 바로. 전달은 감독의 영속 발송함에서 Alertmanager로 짧게 사는 경보를 보내 기존 Telegram 경로로 내보낸다(B-17). 사건 하나에 글이 한 번만 오는지(지금 Alertmanager의 4시간 반복과 해소 글), Telegram으로만 가는지(D-28), 재시작에서 빠지거나 겹치지 않는지 검증한다. 안 되면 조사 초안의 안(발송함을 읽는 모델 없는 전달기)으로 바꾸고 관리자에게 알린다.

## 완료 조건

- [ ] 흉내 낸 한도 실패에서 순서대로 한 번만 넘어가고 알림이 한 번 온다(AC-15).
- [ ] CLI 수동 전환이 되고, Discord 요청은 거절된다(AC-16).
- [ ] 경고만으로는 넘어가지 않는다. 재시도 중 신호(`system/api_retry`)로도 넘어가지 않는다.
- [ ] 감독을 재시작한 뒤에도 소진 상태는 그 계정의 다음 지급 예정일 뒤에 자동으로 다시 확인되고, 잠김 상태는 CLI로 풀기 전까지 그대로다.
- [ ] 지급 예정일이 20일인 계정의 소진 상태는 다음 달 1일에 다시 확인되지 않고 20일 뒤에 확인된다.
- [ ] 흉내 낸 구독 인증 실패에서 그 구독만 잠기고 다음 후보로 넘어가며 알림이 바로 한 번 온다. 잠금은 재시작·새 자격으로 풀리지 않고 `unlock`으로만 풀린다. 같은 계정의 API는 잠기지 않는다(D-40).
- [ ] 흉내 낸 `oauth_org_not_allowed`·`account_on_hold`에서는 다음 후보로 넘어가지 않고 그 역할이 기다리며 알림이 온다(D-40).
- [ ] 만료가 30일 안인 토큰이 있으면 하루 한 번 오는 글에 그 줄이 실린다(D-40).
- [ ] `--for` 없이 고른 수동 선택은 24시간 뒤, `--for 1h`로 고른 것은 1시간 뒤 다음 안전 경계에서 자동 순서로 돌아간다. `account auto`는 바로 되돌린다. 끝이 없는 수동 선택은 만들 수 없다. 수동으로 고른 계정이 한도에 걸리면 자동 순서로 넘어가고 알림이 온다. 감독을 재시작해도 남은 시간이 유지된다(D-41).
- [ ] 못 가른 API 오류에서 그 API는 잠기지 않고 미상 보류가 되며, 하루 뒤와 지급 예정일 뒤에 실제 작업으로 다시 확인된다(B-17).
- [ ] 전환 알림이 Alertmanager 경로로 사건마다 한 번만 오거나, 안 되는 이유와 바꾼 경로가 "결과"에 있다(B-17).

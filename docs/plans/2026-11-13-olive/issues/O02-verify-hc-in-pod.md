## 목표

오케스트레이터 세션 파드 안에서 hc를 D-37의 규칙대로 쥘 수 있는지 확인한다. 고정 실행기가 띄운 core, core가 띄우는 holder, 그 자식이 모두 같은 파드 경계(cgroup·PID·네트워크) 안에 있는지, 세션마다 새 core에 자격 하나만 줄 수 있는지, 모델 도구에서 hc 소켓이 가려지는지, `watch`가 입력 없이 볼 수 있는지를 본다. 안 되면 B-02의 "막히면"대로 관리자에게 물을 근거를 남긴다. 작업자 파드에는 hc가 없으므로 이 티켓의 대상이 아니다.

## 알려진 사실

- [확인] 설치된 hc는 0.1.17이고, client별 권한·인증이 없다. core 소켓과 holder 소켓에 닿는 쪽은 그 계정의 명령·파일·터미널을 제어한다.
- [확인] hc 0.1.17은 user manager가 있으면 core·holder를 별도 systemd user service로 띄우고 `KillMode=process`를 쓴다. user manager가 없으면 자식 프로세스와 `setsid()`로 띄운다. "core를 강화된 서비스에서 띄웠으니 자식도 같은 경계"라고 가정하면 안 된다.
- [확인] `hc run`은 부른 쪽이 아니라 core의 환경을 프로그램에 넘긴다. API의 env override와 argv는 hc 상태 파일에 남는다. holder가 core를 다시 띄울 수 있다. 종료 뒤 기본 보관은 24시간·500개다. `hc attach --observe`는 화면의 제어 문자를 거르지 않고 core가 없으면 띄운다(`supervisor.md` §2.1).
- [확인] 호스트는 `kernel.apparmor_restrict_unprivileged_userns=1`이다. 지금 작업자 파드는 bwrap용 프로필을 쓴다.
- [미확인] 실제 파드에서 core·holder·후손이 어느 cgroup에 놓이는지. 소스를 읽은 것은 돌려 본 것이 아니다.

## 할 일

실제 자격과 모델 호출 없이, 가짜 표식과 고정 프로그램(예: `sleep`, 입력을 기록하는 프로그램)으로 한 번에 하나씩 한다.

1. 전용 시험 네임스페이스에 비root UID, `automountServiceAccountToken: false`, `enableServiceLinks: false`, 읽기 전용 root, capability drop ALL, privilege escalation 금지인 파드를 띄운다. hostPath·hostPID·hostNetwork 없음.
2. 고정 버전 hc의 core를 PID 1 아래 실행기 역할의 고정 프로그램이 띄운다. 상태·설정·소켓 경로를 세션 폴더 하나 안으로 모은다(짧은 XDG 경로).
3. 포함 관계: core 직접 실행과 client 자동 기동을 나눠, core·holder·프로그램·분리된 후손의 PID·PPID·SID와 호스트에서 본 cgroup을 적는다. holder가 core를 다시 띄운 뒤에도 같은 파드 하위 트리인지 본다. 파드 limits(CPU·메모리)가 holder에도 걸리는지 본다.
4. 종료와 소멸: core SIGTERM·SIGKILL, holder 실패, `--outlive-parent`, 세션을 분리한 자식, 파드 종료를 다룬다. hc 기록이 끝남이어도 노드에 후손이 남는 경우를 잡는다. 파드 종료 뒤 그 파드 UID의 cgroup이 비는지 NUC에서 sudo 없이 읽는다(D-39의 노드 확인과 같은 방법).
5. 소켓 가림: 모델·도구 역할에서 client 소켓, 모든 holder 소켓, hc 상태·설정 경로, `/proc`·fd·symlink 별칭에 닿는지 본다. 다른 컨테이너·파드에서 소켓이 보이지 않는지 본다.
6. 자격과 상태 잔존: 실행 A·B에 서로 다른 가짜 env 표식을 넣고 "새 core"와 "기존 core"에서 프로그램이 무엇을 받는지 본다. env override가 상태 파일에 남는 것을 확인한다. 종료·삭제·core 재시작 뒤 상태·로그·화면 기록·컨테이너 로그가 남는 자리를 목록으로 만든다(O18에 넘긴다).
7. 보기: `watch`가 쓸 읽기 경로에서 키·붙여넣기·크기 변경·포커스·단말 질의 응답이 프로그램에 가지 않는지 본다. 제목·링크·클립보드 쓰기의 무해한 표본으로 관리자 쪽 정제가 제어 문자를 실행하지 않는지 본다(운영 단말의 실제 클립보드에 시험하지 않는다). core가 없을 때 보기가 core를 띄우지 않는지 본다.
8. 결과를 "결과" 절에 적고, B-02를 유지할지 관리자에게 물을지 안을 낸다. 시험 파드는 되돌린다.

- 수행: 에이전트

- 대화 방식의 기준: `discord.md`(말투, 한 줄로 말하고 바로 진행, 번호 선택지, 결과 글의 모양)
- 설계 계약: `supervisor.md`(§2 hc를 쥐는 규칙, §4 도구 열 개, §5 관리 설정, §6 세션 교체), 보안 조사 1·3.4·5.2절, 효율 조사 1·8절, 기억 조사 9절, O02·O03 결과. O02(B-02 유지)가 넘긴 것: 같은 컨테이너의 모델·도구는 hc 소켓·상태·다른 프로세스의 환경에 닿고 이 파드 설정에서는 user 네임스페이스를 못 쓴다. 그래서 소켓 가림은 D-47(`supervisor.md` §2.4)이 맡는다: 본체 컨테이너 분리, 중계(바이트와 닫기만, 고정 크기, 중계 폴더는 제어 쪽 소유이고 본체에는 읽기 전용), 자격은 새 세대 확인 뒤 중계와 다른 통로로 본체에게만, 세션 교체는 전체 컨테이너 재시작에 묶는 안. O25가 그 성립을 실측하고, 도구 정책(할 일 1·2)은 보조 통제로 그대로 만든다. `watch`는 소켓 직접 확인 뒤에만 읽는다(hc의 읽기 명령은 core가 없으면 띄운다). `memory.oom.group=1`이라 한 프로그램의 메모리 초과가 같은 컨테이너의 core·holder·실행기를 함께 내린다

## 목표

세션 파드의 hc 안에서 오래 사는 올리브 세션이 좁은 도구만으로 요청을 받아 작업을 나누고 결과를 묶어 답한다. hc는 그 파드의 실행기가 감독의 서명된 지시로만 쥔다. 세션이 바뀌어도 맥락이 인계 문서와 기억으로 이어진다.

## 할 일

0. 세션 파드와 실행기(D-37, `supervisor.md` §2.2): 세션 파드에 고정 실행기를 두고, 실행기만 hc를 쥔다. 감독의 서명된 세션 지시(O09의 계약)가 있을 때만 core를 띄우고 hc 터미널로 중계를 연다. Claude Code는 본체 컨테이너에서 고정 명령으로 뜬다(D-47, `supervisor.md` §2.4).
   - 두 컨테이너: 제어 컨테이너(세션 실행기, hc core·holder, 중계 클라이언트)와 본체 컨테이너(다른 uid·gid, 중계 서버, Claude Code, MCP 연결부, 관리 훅). `shareProcessNamespace: false`. 본체 컨테이너에는 hc 실행 파일·소켓·상태가 없다. 중계는 고정 터미널 하나의 바이트와 닫기만 나르고 명령·인자·환경을 받지 않는다. 화면은 고정 크기다. 중계 폴더는 제어 쪽 소유이고 본체에는 읽기 전용이다.
   - 세션마다 새 core: 하루 교체와 계정 세대가 바뀔 때마다 core를 새로 띄운다. 구독 자격은 core 환경에 넣지 않고, 새 세대가 확인된 뒤 중계와 다른 통로로 본체에게만 준다(`supervisor.md` §2.2 규칙 3의 변경). 자격을 argv나 env override로 넘기지 않는다(hc 상태 파일에 남는다 [확인]). 실행기 자신의 키는 core 환경에도 본체에도 넣지 않는다.
   - hc의 상태·화면·로그 경로를 세션 폴더 안에 둔다. 원문으로 다뤄 168시간 안에 세션 폴더와 함께 지운다(O18). 종료 뒤 기본 보관(24시간·500개)에 기대지 않는다.
   - client 소켓과 holder 소켓을 본체에서 모두 가린다. 가림은 본체 컨테이너 분리가 맡고 도구 정책(할 일 1·2)은 보조다. 같은 파드의 공유 네트워크에 제어 쪽이 여는 수신점은 본체가 직접 붙는다고 보고 인증·거절한다(`spec.md` §5.3). 관리자 개인 hc에 세션 파드를 machine으로 등록하지 않는다.
   - 종료와 교체: 실행기는 본체의 후손을 볼 수 없으므로 세션 교체를 전체 컨테이너 재시작에 묶는다(O09의 계약, O25의 결과대로). 전체 재시작 뒤에도 emptyDir은 남으므로 세대마다 새 경로를 쓴다. `hc kill`, core 종료, 중계의 끝남, 본체의 "끝났다" 응답을 종료의 증거로 쓰지 않는다.
   - 본체 컨테이너의 이미지와 Claude Code 설치(고정 버전, glibc 이미지, 쓰기 가능한 `TMPDIR`·HOME)는 O25의 시험 이미지에서 출발해 안을 낸다(`spec.md` §5.3).
   - 세션 Deployment의 Git replicas는 0이고 켜고 끄기는 `homelab` CLI가 한다(D-38, O09).
1. 실행 도구: Claude Code 대화형(B-01). 관리 설정으로 도구를 아래로만 좁힌다. 셸·파일 쓰기·웹 fetch·MCP 임의 서버는 없다. 확인된 사실과 함정은 `supervisor.md` §5.1이다(`--mcp-config`·`--strict-mcp-config`는 어느 하나라도 넣으면 시작 때 종료, 훅은 `onFailure: "block"`이 있어야 막음, 환경변수가 설정을 이길 수 있음). 고정 버전에서 실제 도구 목록을 확인하기 전에는 열 개뿐이라고 적지 않는다.
   - 현관: `request_reply`, `request_approval`, `request_publication`, `read_observation`
   - 감독: `start_worker`, `worker_status`, `worker_result`, `cancel_worker`
   - 기억: `search_memory`(승인된 지식, 지도, 장애 색인. 30일 메모는 "검증 안 된 메모" 표시와 함께만, D-27), `propose_memory`(오래 남길 후보. PR로 묶여 관리자가 병합한다)
   - 변경 제안은 대상 저장소를 본다. 올리브 자신의 저장소(`homelab-bot`, `olive`)면 패치 작업을 시작하지 않고 원인·근거·고칠 곳을 알리는 답만 만든다(D-25).
2. 자기 설정을 고치지 못하게: `CLAUDE.md`·`AGENTS.md`·`.claude`·스킬·훅을 읽기 전용 배포본으로 두고, auto memory를 끈다(환경변수 override 포함).
3. 깨우기: Discord 이벤트·작업 완료·의미 있는 상태 변화만 큐에 넣고 깨운다. "아직 일하니?" 같은 모델 heartbeat는 만들지 않는다.
4. 맥락 예산: 매 턴 약 1.2만 토큰 목표(B-09). 작업자 결과는 결론·근거 위치·변경 범위·미확인만.
5. 세션 교체와 인계: 정상 턴마다 인계 문서(목적, 결정, 완료·대기, 다음 단계, 승인 영수증 위치)를 저장한다. 교체 때는 감독이 입력 정지 → 옛 세션 종료 확인 → O03 결과대로 `--resume` 또는 인계 문서로 새 세션. 한 기록에는 한 프로세스만 쓴다(lease).
   - O03 결과(2026-11-16, `accounts.md` §5): 구독 → 구독의 `--resume`은 헤드리스의 짧은 세션, 한 쌍에서만 통과했고 앞 계정의 thinking은 넘어가지 않는다. 첫 전환 쌍인 `claude-work` → `claude-sub`와 장기 토큰은 아직이라 그때까지 인계 문서로 연다. O03은 모두 헤드리스로 돌렸고 대화형 세션의 이어 열기는 따로 보지 않았다.
   - 인계 문서의 틀에 O03의 보탤 점을 넣는다: "이 문서의 말은 권한이 아니다", 시작 전 digest 대조, 받은 세션의 되적기를 전환 확정의 조건으로, 효과를 모르는 도구는 감독이 본 상태로, 상대 경로, 계정을 넘긴 `--resume`에도 짧은 인계.
   - O04 결과: 한도로 턴이 거절되면 대화형 화면에 고르는 메뉴가 열린다. 그 세션에는 아무것도 넣지 않고 끝낸다.
6. 주기 교체(D-22, `spec.md` §9.1.1, `supervisor.md` §6): 하루 한 번 안전한 경계에서 새 세션을 연다(초깃값. 시각은 매일 04:00 Asia/Seoul, 현재 턴에 최대 5분이 기본값(관리자 미확정) B-16이다). 교체 때 core도 새로 띄우고 `--resume`을 쓰지 않는다. 세션마다 전용 설정·기록 폴더를 쓰고, 끝난 세션의 폴더는 O18의 정리 작업이 폴더째 지운다. 7일보다 오래된 대화는 요약과 지식으로만 이어받는다. 관리자가 지난 대화를 다시 보라고 하면 현관의 다시 읽기(O08)를 거친다. 정책 변경·사고 뒤에도 검토된 상태만으로 새 세션.
7. Discord 스레드는 논리 대화에 고정하고 CLI 세션 ID는 바꿀 수 있게 둔다.
8. 보기(`homelab olive watch`, D-37, `supervisor.md` §2.3): 본체 화면은 세션 실행기의 고정 읽기 전용 내보내기에서, 작업자가 하는 일은 감독 장부의 실행 목록·단계·정제된 출력에서 받는다. 관리자 쪽 CLI 코드가 제어 문자를 걸러 그린다. 입력(키, 붙여넣기, 크기 변경)을 보내지 않는다. 없는 core를 띄우지 않고, 정지 중이면 볼 것이 없다고 끝낸다. `hc attach --observe`를 그대로 감싸지 않는다(제어 문자를 거르지 않고 core가 없으면 띄운다 [확인]). 작업자에는 끼어들 수 없고 취소만 된다.

## 완료 조건

- [ ] 셸·원시 hc·클러스터 토큰·GitHub 토큰 접근 시도가 모두 실패한다(AC-07).
- [ ] 세션을 교체하면 새 core가 뜨고 새 세션의 모델 환경에 이번에 고른 자격 하나만 있다(같은 계정이면 같은 토큰 하나다). 계정을 바꾼 뒤에는 앞 계정의 자격이 없다. 고르지 않은 계정·방식의 자격과 실행기의 키는 어느 세션에도 없다. hc 상태 파일, 제어 컨테이너의 프로세스 환경과 인자에 자격 값이 없다. 본체 컨테이너(모델, MCP 연결부, 훅)에서 정확한 경로로 붙어도 hc의 client·holder 소켓에 닿지 못한다(AC-32, D-47).
- [ ] 중계를 거친 실제 인증 대화형 세션(로그인한 Claude Code, MCP 도구 호출, 관리 훅)이 고정 크기 화면에서 돌고, 끝내기와 세션 교체 뒤 옛 본체가 남지 않는다(O25는 자격 없이 첫 화면까지만 본다).
- [ ] `watch`가 본체 화면과 작업자 진행을 보여 주고, 입력을 보내지 않고, 심은 제어 문자를 실행하지 않고, 없는 core를 띄우지 않는다(AC-31).
- [ ] 세션을 강제로 바꾼 뒤 진행 중 작업과 대기 승인이 이어진다(중복 실행 없음).
- [ ] 이벤트 없는 1시간 동안 모델 호출 0번(AC-20).

## 목표

세션 파드의 hc 안에서 오래 사는 올리브 세션이 좁은 도구만으로 요청을 받아 작업을 나누고 결과를 묶어 답한다. hc는 그 파드의 실행기가 감독의 서명된 지시로만 쥔다. 세션이 바뀌어도 맥락이 인계 문서와 기억으로 이어진다.

## 할 일

0. 세션 파드와 실행기(D-37, `supervisor.md` §2.2): 세션 파드에 고정 실행기를 두고, 실행기만 hc를 쥔다. 감독의 서명된 세션 지시(O09의 계약)가 있을 때만 core를 띄우고 hc 터미널로 중계를 연다. Claude Code는 본체 컨테이너에서 고정 명령으로 뜬다(D-47, `supervisor.md` §2.4).
   - 두 컨테이너: 제어 컨테이너(세션 실행기, hc core·holder, 제어 쪽 중계 끝점: 소켓을 만들어 듣는다)와 본체 컨테이너(다른 uid·gid, 본체 쪽 중계 끝점: 그 소켓에 붙는다, Claude Code, MCP 연결부, 관리 훅). `shareProcessNamespace: false`. 본체 컨테이너에는 hc 실행 파일·소켓·상태가 없다. 중계는 고정 터미널 하나의 바이트와 닫기만 나르고 명령·인자·환경을 받지 않는다. 화면은 고정 크기다. 중계 폴더는 제어 쪽 소유이고 본체에는 읽기 전용이다.
   - 세션마다 새 core: 하루 교체와 계정 세대가 바뀔 때마다 core를 새로 띄운다. 구독 자격은 core 환경에 넣지 않고, 새 세대가 확인된 뒤 중계와 다른 통로로 본체에게만 준다(`supervisor.md` §2.2 규칙 3의 변경). 자격을 argv나 env override로 넘기지 않는다(hc 상태 파일에 남는다 [확인]). 실행기 자신의 키는 core 환경에도 본체에도 넣지 않는다.
   - hc의 상태·화면·로그 경로를 세션 폴더 안에 둔다. 원문으로 다뤄 168시간 안에 세션 폴더와 함께 지운다(O18). 종료 뒤 기본 보관(24시간·500개)에 기대지 않는다.
   - client 소켓과 holder 소켓을 본체에서 모두 가린다. 가림은 본체 컨테이너 분리가 맡고 도구 정책(할 일 1·2)은 보조다. 같은 파드의 공유 통로(localhost TCP, abstract 소켓, `/dev/shm`)에 제어 쪽이 여는 수신점은 본체가 직접 붙는다고 보고 인증·거절한다(`spec.md` §5.3). 관리자 개인 hc에 세션 파드를 machine으로 등록하지 않는다.
   - 종료와 교체: 실행기는 본체의 후손을 볼 수 없으므로 세션 교체를 전체 컨테이너 재시작에 묶는다(O09의 계약, O25의 결과대로). 영수증은 다음 세대의 실행기가 새 세대 표식과 한 번 쓰는 시작 허가로 앞 교체를 대조해 인수한 것이다(D-50). 전체 재시작 뒤에도 emptyDir은 남으므로 세대마다 새 경로를 쓴다. `hc kill`, core 종료, 중계의 끝남, 본체의 "끝났다" 응답을 종료의 증거로 쓰지 않는다.
   - 규칙 확인(D-51): 새 세션 파드는 첫 자격 전에 일부러 전체 재시작을 한 번 시켜 재시작 규칙을 확인하고, 규칙이 빠졌으면 자격 0회로 시작을 거부한다.
   - 세션 깨짐(D-52): 본체가 죽거나 본체 컨테이너만 다시 뜨거나 중계가 끊기면 실행기가 감독에 알린다(신호의 형식은 O09의 계약). 실행기가 스스로 전체 재시작하지 않는다. 기동 실패 한도와 `hold`의 모양은 `spec.md` §5.3의 미정이고 이 티켓이 안을 낸다.
   - 본체 컨테이너의 이미지와 Claude Code 설치(glibc·musl 배포본, 쓰기 가능한 `TMPDIR`·HOME), 본체 PID 1의 모양(격리 포함)은 O25의 시험 이미지에서 출발해 안을 낸다(`spec.md` §5.3의 미정, 관리자가 배포 PR에서 본다). O25 2차는 지금 본체 이미지에 musl 배포본 2.1.325를 쓴다(시험용 선택).
   - 버전(D-48): Claude Code의 버전·플랫폼·URL·sha256을 저장소에 고정한다. 설치 방식의 초안은 O25 2차의 모양대로 init이 그 sha256으로 확인한 파일만 본체에 읽기 전용으로 붙여 고정 경로로 실행하는 것이다(초안. 운영 설치 방식은 위 줄과 같이 `spec.md` §5.3의 미정). 본체 환경에 `DISABLE_AUTOUPDATER=1`을 넣는다. O25 시험 도구도 본체 환경을 고정 허용 목록으로 새로 만들어서, 차트 env에만 넣으면 본체에 전달되지 않는다 [확인, 저장소]. 운영 실행기도 같은 모양이면 그 목록에 넣는다. 새 버전은 자동 PR로 올라오고 관리자가 병합하면 다음 세션부터 쓴다. 자동 PR을 만드는 도구와 sha256을 채우는 방법, 맡을 티켓은 미정이다(`spec.md` §5.3).
   - 바깥 통신(D-49): 제품 통계와 오류 보고를 끄는 환경변수(`DISABLE_TELEMETRY`, `DISABLE_ERROR_REPORTING`, `DO_NOT_TRACK`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`)를 넣지 않는다. 자체 OpenTelemetry(`CLAUDE_CODE_ENABLE_TELEMETRY`)는 켜지 않는다. 제품 통계가 가는 곳(`api.anthropic.com`, Datadog 수신점 [문서 확인])을 불변 조건 9의 허용 목적지에 어떻게 넣을지는 이 티켓의 네트워크 안에서 낸다 → 관리자(배포 PR 검토).
   - 세션 Deployment의 Git replicas는 0이고 켜고 끄기는 `homelab` CLI가 한다(D-38, O09).
1. 실행 도구: Claude Code 대화형(B-01). 관리 설정으로 도구를 아래로만 좁힌다. 셸·파일 쓰기·웹 fetch·MCP 임의 서버는 없다. 확인된 사실과 함정은 `supervisor.md` §5.1이다(`--mcp-config`·`--strict-mcp-config`는 어느 하나라도 넣으면 시작 때 종료, 훅은 `onFailure: "block"`이 있어야 막음, 환경변수가 설정을 이길 수 있음). 고정 버전에서 실제 도구 목록을 확인하기 전에는 열 개뿐이라고 적지 않는다.

   - 변경 제안은 대상 저장소를 본다. 올리브 자신의 저장소(`homelab-bot`, `olive`)면 패치 작업을 시작하지 않고 원인·근거·고칠 곳을 알리는 답만 만든다(D-25).

5. 세션 교체와 인계: 정상 턴마다 인계 문서(목적, 결정, 완료·대기, 다음 단계, 승인 영수증 위치)를 저장한다. 교체 때는 감독이 입력 정지 → 옛 세션 종료 확인 → O03 결과대로 `--resume` 또는 인계 문서로 새 세션. 한 기록에는 한 프로세스만 쓴다(lease).

## 완료 조건

- [ ] 셸·원시 hc·클러스터 토큰·GitHub 토큰 접근 시도가 모두 실패한다(AC-07).
- [ ] 세션을 교체하면 새 core가 뜨고 새 세션의 모델 환경에 이번에 고른 자격 하나만 있다(같은 계정이면 같은 토큰 하나다). 계정을 바꾼 뒤에는 앞 계정의 자격이 없다. 고르지 않은 계정·방식의 자격과 실행기의 키는 어느 세션에도 없다. hc 상태 파일, 제어 컨테이너의 프로세스 환경과 인자에 자격 값이 없다. 본체 컨테이너(모델, MCP 연결부, 훅)에서 정확한 경로로 붙어도 hc의 client·holder 소켓에 닿지 못한다(AC-32, D-47).

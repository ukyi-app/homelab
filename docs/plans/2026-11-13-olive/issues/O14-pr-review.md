- 상태: 대기 (선행: O08, O10, O12)
- 명세: `spec.md` §2.1(PR 리뷰), §7(PR 리뷰 작업자 줄), §5.2 B-08
- Blocked by: O08, O10, O12
- 연결 AC: AC-14
- 결정(관리자): D-06(Discord 요청 → PR에 리뷰 → Discord 요약, 지금 리뷰 App 신원 그대로)
- 수행: 에이전트
- 저장소·PR: `olive` 저장소 PR, 봇 저장소 PR(현관의 리뷰 게시 경로)
- 파일 소유: PR 리뷰 역할 프로필, 현관의 리뷰 게시·요약 경로
- 설계 계약: 보안 조사 7절 F-1, 옛 봇 C30(리뷰 요청)

## 목표

관리자가 Discord에서 PR 리뷰를 부탁하면, 리뷰 작업자가 초안을 만들고 현관이 지금 리뷰 App으로 PR에 리뷰를 달고, Discord에 짧은 요약을 남긴다.

## 할 일

1. 요청: 오케스트레이터가 대상 PR(저장소·번호)을 확인하고 감독에 `start_worker(role=review)`를 요청한다. 대상 저장소는 리뷰 App이 설치된 곳만.
2. 입력: 현관(신뢰 수집기)이 diff·메타데이터를 고정 revision으로 넘긴다. PR 본문·댓글처럼 남이 쓴 글은 격리 읽기(O12) 규칙을 따른다.
3. 실행 도구: Codex(B-08, 기본값(관리자 미확정)). 필수 스킬 "PR 리뷰".
4. 게시: 현관이 리뷰 본문·인라인 댓글·경로를 공개 검사(F-1) 뒤 리뷰 App으로 단다. 병합·승인(approve) 상태는 쓰지 않는다(지금 리뷰 App 동작 유지, O07에서 확인).
5. Discord 요약: 결론과 큰 지적 수만. 공개 검사 거침.
6. 남의 PR(fork·외부 기여자·봇)도 체크아웃하거나 그 트리의 훅·검사를 돌리지 않는다.

## 완료 조건

- [ ] Discord 요청 → PR에 리뷰 → Discord 요약이 이어진다(AC-14).
- [ ] 리뷰 본문에 심은 가짜 비밀이 게시되지 않는다.

## 검증

- 경계: 시험 PR 하나에 실제 리뷰(모델 호출), 운영 확인은 O21.
- 잡는 실패: 다른 신원 사용, 검사 없는 게시. 못 잡는 범위: 리뷰 품질.

## 목표

지금의 샌드박스 작업자(bwrap, 자격 env 제거)를 재사용해 감독이 띄운 코드 작성 작업이 고정 snapshot에 패치를 만든다. 검증은 네트워크 없는 검증 실행기가 고정 명령으로 돌린다.

## 할 일

1. 감독의 `start_worker(role=author)`가 지금 샌드박스 작업자 엔드포인트를 부르는 연결부를 만든다. 원시 hc 소켓을 샌드박스에 마운트하지 않는다.
2. 실행 도구: 크레딧 단계는 OpenCode, 구독 단계는 Claude Code(D-15, B-08). 지금 샌드박스 작업자는 Claude Code만 돌리므로 OpenCode 실행 경로를 더한다. 두 도구 모두 모델 자격은 실행 env에만 있고 도구 env에서는 제거한다(지금 동작 유지). 패치 결과의 모양과 검증은 도구와 무관하게 같다.
3. bwrap 실패 때 무샌드박스로 넘어가지 않는다. 실패면 실행 0건.
4. 검증 실행기: 고정 명령 ID(예: `pre-commit run --files`, `bun run ci`)를 네트워크 없는 샌드박스에서 돌린다. 머신 전체 시험 잠금을 쓴다.
4-1. 반박 검토(D-34): 올리브가 스스로 고치는 경우(관리자가 말로 시킨 변경은 아님), 패치를 만들기 전에 다른 계열 모델(Codex, PR 리뷰 역할 프로필)이 진단 메모와 근거 영수증을 보고 다른 설명이 가능한지 찾는다. 관측 중계로 같은 범위를 다시 읽을 수 있다. 그럴 만한 반박이 나오면 감독이 등급을 그럴듯으로 내리고 패치로 넘어가지 않는다.
5. 자체 리뷰: 결과 패치를 PR 리뷰 역할로 한 번 본다. 그 역할 프로필(실행 도구, 자격, 상한)은 O09의 역할 표에 있으므로 O14를 기다리지 않는다. O14는 Discord 요청에서 GitHub 리뷰 게시까지의 흐름을 만든다. "PR 리뷰" 스킬(O20)이 아직 없으면 저장소의 리뷰 규칙(`AGENTS.md`)만으로 본다.
6. 필수 스킬 "homelab PR 작성"을 계약에 넣는다(O20).
7. 결과: 패치 artifact(불변, digest), 검증 영수증, 자체 리뷰 영수증. 게시는 O15.

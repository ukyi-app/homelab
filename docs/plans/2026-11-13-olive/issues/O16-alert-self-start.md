## 목표

critical 경보가 울리면 올리브가 진단 작업자를 띄워 원인을 찾고, 고칠 수 있으면 PR을 올린다(O15). warning은 알리기만 한다. 기존 Telegram 경로는 그대로다.

## 할 일

1. 수신: 지금 vmalert → Telegram 경로는 건드리지 않고, 같은 경보를 현관으로도 보낸다(방법은 이 티켓이 정한다. 현관이 경보 출처를 검증한다).
2. 분기: `severity: critical` → 스스로 진단. `warning` → 알림만. `none` → 무시.
3. 다시 할지와 차단기(D-28, `spec.md` §11.3). 판정은 감독의 코드가 하고 모델에 맡기지 않는다.
   - 묶음: 진단을 바로 시작하고, 도는 동안이나 시작 뒤 5분 안에 울린 다른 심각 경보는 그 진단에 붙인다.
   - 풀려도 끝까지: 경보가 풀려도 진단을 마친다. "resolved" 알림은 새 경보로 보지 않는다.
   - 앞 결과를 본다(장애 색인, O19): 올리브 PR이 열려 있으면 알림 한 번만, 사람 몫이었으면 그 일을 다시 알림, 수정이 병합된 뒤 재발이면 다시 진단, 원인을 못 찾았으면 1시간 뒤에도 울리거나 다시 울릴 때 한 번 더.
   - 차단기: 경보 하나당 하루 3번, 전체 하루 5번. 걸리면 알림만. 진단 한 번의 시간·토큰 상한은 O11의 역할 프로필 값을 쓴다.
   - 손으로: 관리자가 봐 달라고 한 진단은 차단기와 상관없이 돌고 자동 횟수에 세지 않는다.
   - 잠시 끄기: `homelab` CLI에 자동 진단을 정한 시간 동안 끄는 명령을 둔다(O09의 올리브 관리 명령에 더한다). 시간이 지나면 저절로 켜진다. Discord에서는 켜고 끌 수 없다(현관이 CLI 안내로 거절).
4. 제외(D-28): 올리브 자신·모델 한도·삭제 원장 경보는 진단하지 않고 Telegram으로만.
5. 결과: 원인을 찾고 고칠 수 있으면 PR(O15). 못 찾으면 조사 내용만 알림. 사람만 할 수 있는 일이면 그 일을 적어 알림.
5-1. 장애 색인(D-27, `spec.md` §9.2)을 이 티켓이 만든다. 감독이 진단 실행마다 한 줄을 적는다. 칸은 경보 이름, 시작·끝 시각, 진단 실행 ID, PR 번호, 결과 enum(원인 찾음, 못 찾음, PR 올림, PR 병합됨, 사람 몫). 자유 글 칸을 두지 않는다. 상태 볼륨에 두고 백업한다. PR의 열림·병합 상태는 현관이 알려 준다.
6. 필수 스킬: 진단 공통 + 그 경보의 스킬(O20). 스킬이 없는 critical 경보는 진단 공통만.
7. 경보 문자열(라벨·annotation)은 외부 입력으로 보고 진단 작업자에게 구조화 필드로만 넘긴다.
8. 올리브 자신 경보 목록 안(O09와 함께): 감독 죽음, 비상 정지 상태, 대기열 정체, 계정 전부 막힘 등.

## 목표

모델이 아닌 감독이 올리브 전용 hc core를 혼자 쥐고, 고정 역할의 작업자만 띄우며, 예산·동시 실행 상한과 비상 정지를 집행한다.

## 할 일

0. 저장소 등록(D-18, `spec.md` §4.1): 관리자가 이름을 정한 뒤 `infra/github/app-repos.json`에 넣는 homelab PR을 올리고, 관리자가 Terraform apply와 템플릿 저장소에서 만들기를 한다(외부 변경, `approvals.md`에 기록). `CODEOWNERS`, `AGENTS.md`, Dockerfile의 버전 고정 검사를 봇 저장소 것에서 가져와 맞춘다. `apps/`에는 등록하지 않는다. 이미지는 `platform/` 값에 digest로 고정하고 사람 PR로만 올린다.
1. 배치: O02 결과대로 별도 파드(B-02) 또는 호스트 전용 계정. 관리자 개인 hc core·계정 폴더를 마운트하지 않는다. 원시 hc 소켓은 감독 밖에 노출하지 않는다.
2. 역할 표: 진단, 격리 읽기, 코드 작성, PR 리뷰, 기억 정리. 역할마다 고정 프로필(실행 도구, 모델, 자격, 네트워크, 필수 스킬, 시간·토큰 상한). 임의 명령·이미지·볼륨을 받는 API는 만들지 않는다.
3. 작업자 띄우기 API(오케스트레이터용): `start_worker(role, task)`, `worker_status`, `worker_result`, `cancel_worker`. 결과는 모양·크기 검사(1~2천 토큰 목표) 뒤 돌려준다. 원문 로그·사고 과정은 넘기지 않는다.
4. 상한(B-07): 오케스트레이터 1, 작업자 1(나머지는 대기열), 올리브 전체 CPU 4개·메모리 8GB·PID 상한. 시험·빌드는 머신 전체 잠금(같은 inode)을 쓰고 잠금 획득 뒤 전체 시간 제한을 건다.
5. 유휴 호출 끄기(B-09): 관리 설정으로 prompt suggestions·away summary·idle compaction·goal check-in을 끄고 `autoContinueAtUsageLimit=false`. 환경변수 override도 막는다.
6. 비상 정지(§6-8): 현관이 먼저 새 요청·capability 발급을 닫고 → 감독이 전체 실행을 끝내고 holder·분리 자식 0개를 확인 → 확인 실패면 닫힌 채 유지. 재시작 뒤에도 유지. 걸기·풀기는 `homelab` CLI 전용이다(D-21). Discord 문구로 거는 길은 만들지 않는다.
7. 감독 자신의 상태 지표(살아 있음, 대기열, 비상 정지, 작업자 수)를 내보낸다. 올리브 자신에 대한 새 경보 목록 안을 O16과 함께 낸다.
8. 계정 선택은 이 티켓에서 자리만 만든다(지금 계정 하나 고정). 순서·전환은 O17.

## 완료 조건

- [ ] 오케스트레이터가 감독 API 밖으로 작업자를 띄울 수 없다.
- [ ] 두 작업을 동시에 요청하면 하나는 대기한다. 상한을 넘지 않는다(AC-09).
- [ ] 비상 정지 뒤 holder·작업자 0개, 감독 재시작 뒤에도 정지 유지(AC-08).
- [ ] `homelab` CLI로 상태 보기, 비상 정지 걸기·풀기가 된다.

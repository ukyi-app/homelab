- 설계 계약: `docs/runbooks-public/`, `platform/observability/stack/vmalert/rules/`

## 목표

스킬 10개의 첫 판이 관리자 검토를 거쳐 들어가고, 필수 스킬을 실제로 썼는지 감독이 확인한다. 이후 스킬은 PR로만 바뀐다.

## 할 일

1. 첫 판 10개(§10.1). 각 스킬에 볼 것, 흔한 원인, PR로 고칠 수 있는 것, 사람만 할 수 있는 것, 멈출 조건. 재료는 공개 런북과 경보 규칙의 주석. 경보 이름은 규칙 파일과 맞춘다.
2. 공통 4의 내용:
   - 진단 공통: 읽기 범위(D-05), 질의 상한, 비밀 검사, 진단 메모 모양.
   - homelab PR 작성: 저장소 `AGENTS.md` 규칙(버전 고정, 공개 저장소에 두는 것, 주석 규칙), PR 본문 틀.
   - PR 리뷰: 한국어 리뷰 규칙, 요약 모양, 남의 PR 트리를 실행하지 않음.
   - 기억 후보 쓰기: 후보 필드, 출처, 넣지 말 것.
3. 공개 저장소 규칙: 스킬은 비공개 저장소에 두지만, 스킬이 만드는 글은 공개될 수 있으므로 tailnet 이름·IP·개인 정보를 스킬 본문에 넣지 않는다.
4. 필수 스킬(B-04, 기본값(관리자 미확정)): 감독이 역할·경보마다 필수 스킬을 계약에 적고, 작업자 기록에서 호출을 확인한다. 부르지 않은 실행은 "필수 스킬 미사용"으로 표시하고 PR 게시로 넘기지 않는다. 오케스트레이터에는 후보 이름만 가볍게 넣는다. 관리자가 "스킬 평가 강제 UserPromptSubmit 훅"을 원하면 이 줄을 바꾼다.
5. 수정 흐름: 올리브가 스킬 수정 PR을 지식 저장소에 올린다 → 관리자 병합 → 감독이 다음 세션부터 승인된 revision을 읽기 전용으로 배포. 실행 중 세션의 스킬은 바뀌지 않는다.
6. 스킬이 권한을 요구해도 실행 정책은 감독·현관이 정한다. 스킬로 권한이 늘지 않는다.

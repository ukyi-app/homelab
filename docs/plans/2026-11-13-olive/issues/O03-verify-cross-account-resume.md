## 목표

한 계정의 Claude Code 세션을 끝낸 뒤, 다른 계정(구독 → 구독) 또는 다른 방식(구독 → API 키 `-p`)으로 같은 세션을 `--resume`할 수 있는지 확인한다. 안 되면 인계 문서로 새 세션을 여는 방식을 기본으로 정한다.

## 알려진 사실

- [확인] 실행 중 프로세스의 자격을 밖에서 바꾸는 공식 인터페이스는 없다. 전환은 "입력 정지 → 턴 확정 → 옛 프로세스 종료 확인 → 새 자격으로 resume"이다.
- [확인] `--resume`은 압축 전 전체 대화를 다시 싣지 않고, 중단된 도구를 다시 돌리지 않으며, 백그라운드 실행 상태를 복원하지 않는다.
- [확인] 세션 기록은 config 폴더 아래 프로젝트 경로별로 저장된다. 최신 문서는 절대 기록 경로로 `--resume`도 설명한다(설치본 help에는 없음).
- [미확인] 계정이나 인증 방식을 넘나든 `--resume`을 모델 쪽이 받아들이는지.

## 할 일

1. 올리브 전용 시험 config 폴더 두 개를 만든다. 관리자 개인 계정 폴더를 쓰지 않는다. 자격 값은 관리자가 넣는다.
2. 짧은 대화(모델 호출 몇 번)를 계정 A로 만들고 끝낸다. 종료를 확인한다.
3. 같은 기록을 계정 B(구독)로, 그리고 같은 계정 A의 API 키 `-p`로 각각 이어 연다. 기록 파일을 옮겨야 하면 어떤 파일(기록, 부속 폴더)이 필요한지 적고, 자격·계정 설정은 옮기지 않는다.
4. 각 경우의 성공 여부, 이어진 맥락의 범위(앞 대화를 기억하는지), 오류 모양을 적는다.
5. 결과에 따라 `spec.md` §8.2 4번과 O10·O17의 인계 방식을 고친다.

# 복구 자산: 보관 위치와 항목 이름

클러스터, Infisical, 계정을 잃었을 때 처음 손에 쥐어야 하는 것들이다. 근거는 설계 [C.6.4](../plans/2026-10-17-homelab-rebuild/platform/design.md)(최초 연결과 재해 복구)다.

저장소가 public이라(D-23) 이 문서에는 **보관 위치 이름과 항목 이름만** 둔다. 값, 계정 이름, 보관 경로, 각 항목의 세부는 저장소 밖 목록에 있다. 복구 순서는 설계 C.6.4의 "복구 순서" 표를 따른다.

## 보관 위치 (NUC 밖 두 곳)

1. 비밀번호 관리자(1Password)
2. 오프라인 암호화 USB

한 곳만 두지 않는다. 단일 디스크 단일 사본은 매체 유실에 무방비였다(설계 C.6.4).

## 항목

항목 이름은 설계 C.6.4 "복구 자산의 종류" 표와 같은 수준으로만 적는다. 어느 계정·identity·버킷의 것인지, 값과 경로는 저장소 밖 목록에 있다.

| 항목 | 쓰는 상황 |
|---|---|
| 계정 접근 수단(로그인과 2FA 복구 코드) | 모든 복구의 출발점 |
| ESO 부트스트랩 자격 | 클러스터 재구축([bootstrap.md](bootstrap.md) 2.2). 회전은 [rotate.md](rotate.md) 1절 |
| Terraform state 버킷 자격 사본 | Infisical 없이 네트워크 설정 복구 |
| Infisical 암호화 내보내기(분기 1회) | Infisical 계정 잠김·영구 손실, Infisical 장애 중 급한 재구축(클러스터 유실과 겹치면 [restore.md](restore.md) 3.1의 손 Secret) |
| 관리자 비밀번호 원문 | 플랫폼 UI 로그인. 회전은 [rotate.md](rotate.md) 2절 |
| R2 백업 읽기 자격 사본 | Infisical 없이 DB 복원, 시나리오 13. 백업 버킷을 만드는 T11이 더한다 |
| DNS 필터 라이브 설정 내보내기(선택) | UI에서만 바꾼 규칙 복구. T08a 뒤 |

**Infisical 암호화 내보내기의 형식.** `{project, env, at, secrets: {"<Infisical 경로>": "<값>"}}` JSON 하나를 age 암호문구로 암호화한 파일이다(age 버전은 `.tool-versions`). 만드는 블록은 [restore.md](restore.md) 3.1 2)다. 그 블록은 손 Secret 지도의 키만 담는다. 운영 분기 내보내기도 이 형식으로 만든다. 키가 더 있어도 되고, 프로젝트·환경 값(`homelab`/`prod`)이 맞아야 restore.md 3.1의 손 Secret 블록이 그대로 쓴다. 암호문구는 비워 두지 않는다(비우면 age가 만든 암호문구를 화면에 찍는다). 2026-10-29 U40 시험이 이 형식(`homelab-dev`/`dev`, 키 17개)으로 실제로 복호화·사용했다.

**H2(봇 작업자 자격) 뒤 운영·VM 내보내기를 새로 뜬다.** 분기를 기다리지 않는다. sandbox가 실제 작업자로 바뀐 뒤(T16b S11) 손 Secret 지도에 `/apps/homelab-bot/worker/CLAUDE_CODE_OAUTH_TOKEN`이 들어가, 그 전 내보내기로는 restore.md 3.1 4)가 `missing`으로 멈춘다. 작업자 실행기 프로필을 바꿔 자격 키가 바뀔 때(`platform/sandbox/values.yaml`의 `worker.profile`)도 같다. 운영 토큰을 재발급했을 때도 새로 뜬다(옛 내보내기는 철회된 토큰을 담는다). 운영 사본을 바꾸는 순서는 아래 "신선도 확인"의 내보내기 항목과 같다(두 곳을 바로 덮어쓰지 않는다). VM 내보내기는 VM 시험 직전에 뜨므로 그때 `homelab-dev`에 이 키가 가짜 모양 값으로 있어야 한다([bootstrap.md](bootstrap.md) 2.2 vm 1단계).

## 신선도 확인 (분기 1회)

"사본이 있다"가 아니라 "지금 값과 맞다"를 본다.

- 운영 ESO 자격으로 Infisical Universal Auth 로그인이 200인지 본다. 명령은 [rotate.md](rotate.md) 1절 2단계와 같고, 응답 코드만 본다. 2026-10-20 T09 시나리오 7의 장애 주입 뒤에도 200이었다.
- Infisical 암호화 내보내기를 새로 만든다. 두 곳의 사본을 바로 덮어쓰지 않는다. 이 파일은 Infisical을 잃었을 때 값을 되살리는 유일한 원본이라, 잘못 내보내거나 손상된 파일로 두 곳을 함께 바꾸면 마지막 정상 사본까지 사라진다.
  1. 새 내보내기를 복호화해 본다. 평문은 화면에 띄우지 않고 메모리에서만 다룬다.
  2. 저장소 밖 목록의 필수 키 이름이 모두 있는지 키 이름만으로 대조한다.
  3. 그다음 한 곳씩 새 사본을 더한다. 직전 세대 하나는 다음 분기 확인 때까지 남기고, 그보다 오래된 세대만 지운다.
- 시나리오 13(VM 재구축)이 이 자산과 VM 준비 자산으로 실제 복구를 검증한다. VM은 운영 ESO 자격 대신 VM 전용 ESO 자격을 쓰므로 운영 자격은 위 로그인으로 따로 본다.
- 자격을 회전하면 그 자리에서 두 곳을 함께 바꾼다. 한쪽만 바꾸면 복구 때 어느 값이 맞는지 모른다.

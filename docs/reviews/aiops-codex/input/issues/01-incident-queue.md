# 01 — 사건 계약과 영속 큐

Status: needs-info
Blocked by: Q13 전체 설계 확인
Design: [실행·사건 상태](../design.md#4-사건실행게시-상태)

## 결과

같은 장애의 반복 알림은 사건에 합쳐지고, worker 재시작 후에도 미처리 사건·실행 예산·게시
상태가 남는다. 장애 해소와 AI 실행 성공을 독립적으로 표현한다.

## 구현 범위

1. 사건 입력 계약에 source/event ID, 대상, 발생·수집 시각, firing/resolved, severity,
   reason, revision과 증거 참조를 정의한다. 비신뢰 문자열 길이와 전체 요청 크기를 제한한다.
2. durable store가 사건·관측·실행 시도·게시 상태를 소유한다. 수신 성공은 저장 완료 뒤
   반환하고, 재시작 때 단일 worker lease와 실행 결과 불명 상태를 복구한다.
3. 사건 묶음은 source·객체·revision·실패 종류를 검증한다. 대상 이름만 같은 원인은
   합치지 않는다. 늦게 온 firing이 더 새로운 resolved를 무조건 되돌리지 않는다.
4. Codex 동시 실행 1건과 KST 일일 20회 계상을 admission에서 원자적으로 처리한다.
   재시도·재진단도 계상하고, 프로세스 사망으로 예약 상태가 불명하면 예산을 임의 환급하지 않는다.
5. critical 우선·장기 대기 처리·초과 묶음 통지·자기 반복 억제를 정의한다. 모델 실행 재시도와
   Telegram/PR 재전송은 별도 상태다. 저장 실패와 사건 없음은 같은 결과로 반환하지 않는다.

코드 후보 위치는 `tools/lib/aiops/`와 `tools/aiops.ts`다. 파일 이름과 저장소 엔진은
레포 관례에 맞춰 구현 시 정하되 호출부에서 SQL/파일 잠금 정책을 다루지 않게 한다.

단계 deadline과 전체 처리 시도 deadline은 worker 밖의 신뢰된 감독기가 집행한다.
시간/메모리/출력 초과 시 실패 단계·원인을 기록하고 실행 cgroup에 TERM→최대 10초 뒤 KILL을
적용한다. 자식 종료 확인 뒤에만 lease를 해제해 다음 사건을 처리한다. worker 사망 후 복구도
잔존 cgroup을 확인한다. 정리 여부를 확인할 수 없으면 `cleanup-unknown`으로 새 실행을 차단하고
통지하며, lease 만료만으로 동시 실행을 허용하지 않는다. 상한은 design.md 5절을 따른다.

## 완료 증거

모델·네트워크 없이 실제 임시 durable store로 중복/역순/동시 admission, 날짜 경계,
20회 초과, crash 후 재개, 해소 중 실행 취소, 게시 재시도만 수행하는 사례를 검증한다.
재시작 뒤 사건이 사라지거나 동일 slot이 두 실행에 허용되면 완료하지 않는다.
살아 있지만 멈춘 worker와 무한 검증 자식을 주입해 외부 감독의 제한 시간 후 실패 기록,
자식 정리, lease 해제와 다음 사건 처리를 확인한다. 정리 확인 실패 대조군에서는 다음 실행을
차단해야 한다. 게시 단계 timeout은 별도 게시 대조 상태로 복구하고 Codex 예산을 재소비하지 않는다.

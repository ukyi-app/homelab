# AIOps 파일럿 구현 작업

Status: needs-info
Updated: 2026-09-12
Blocked by: Q13 전체 설계의 공유 이해 확인

## 확정한 개발 순서

사용자 선택에 따라 `codex exec`로 파일럿을 먼저 구현한다. Polyrelay는
[채택 조건](deferred-polyrelay.md)을 만족한 뒤 후속 연결한다. 사건 실행 인터페이스 하나로
교체 지점을 확보하고 두 실행기를 동시에 구현하거나 자동 전환하는 기능은 추가하지 않는다.

요구는 [spec.md](spec.md), 동작과 제안 기본값은 [design.md](design.md)가 소유한다.
이 파일과 티켓은 검토용 구현 계획이다. 코드 작성·설치·실제 사건 처리는 아직 시작하지 않았다.

## 작업과 의존성

| 순서 | 작업 | 선행 작업 | 완료 시 확인할 동작 |
|---|---|---|---|
| 1 | [사건 계약·영속 큐](issues/01-incident-queue.md) | Q13 | 재시작·중복·역순 통지에도 사건과 일일 슬롯이 보존됨 |
| 2 | [전체 알림 연결](issues/02-notification-sources.md) | 1 | 5개 생산자 계열의 실패·경고·해소가 큐에 도착함 |
| 3 | [증거·격리 Codex 실행](issues/03-evidence-codex-runner.md) | 1 | 고정 revision과 선별 증거에서 진단·패치가 생성됨 |
| 4 | [검증·fork PR·Telegram](issues/04-validation-publication.md) | 1·3 | 검증한 산출물로 Draft PR과 요약을 중복 없이 게시함 |
| 5 | [NUC 배선·파일럿 수용](issues/05-nuc-pilot-acceptance.md) | 1~4 | 모든 알림·권한·실패 사례를 확인한 뒤 실제 관찰을 시작함 |

1번부터 구현한다. 2번과 3번은 같은 사건 계약을 사용하며 상대 구현을 기다리지 않고 모의
입력으로 검증할 수 있다. 개발 단계에서 일부 생산자를 먼저 연결해도 최종 파일럿 범위를
축소하지 않는다. 전체 연결 이전 상태를 파일럿 완료로 표시하지 않는다.

## 최종 확인할 기본값

| 항목 | 제안 |
|---|---|
| 실행 | 동시 1건·KST 하루 20회. 재시도도 계상. Codex 합계 10분, 수집 2분·검증 합계 5분·게시 시도 1분, 전체 처리 시도 20분 |
| 실패 | 근거 부족은 보류. 실행/사용량 결과 불명은 자동 재시도 금지. 인증·구독 한도 회복까지 대기 |
| 증거 | 사건 전 15분부터 수집 시점까지. 컨테이너당 선별 로그 200줄·증거 합계 256 KiB부터 시작 |
| 보존·자원 | 사건/진단 30일·선별 증거/실행 로그 7일. 단계별 메모리·출력 상한은 design.md 5절. 외부 감독기가 cgroup 전체 종료와 자식 정리를 확인 |
| 평가 | 정답을 분리한 고정 사례 최소 12개, 모든 생산자 수용 후 실제 알림 14일 관찰. 사건 수 부족 시 평가 미완료 |

원인 후보·근거·다음 확인과 수정 초안은 자동 작성한다. 운영 적용은 Draft PR 검토 뒤의 별도
절차다. 외부 앱 소스 변경, API 과금 전환, Polyrelay 구현은 이 작업에 포함하지 않는다.
기존 사용자 선택은 다시 묻지 않고 위 구현 기본값과 전체 이해를 한 번에 확인한다.

## 1차 적대적 리뷰 반영

2026-09-12 사용자가 공통 6건의 수용과 a4 보류를 확정했다. 구현 전 설계 보완이며 원래
Q13 상태를 임의로 완료 처리하지 않는다.

| 판정 | 반영 작업 | 반드시 증명할 동작 |
|---|---|---|
| a2·b3 수용 | 01·03·04·05: 단계별 외부 감독과 제한 시간·자원·출력 상한 | 검증 무한 대기/출력 폭주를 정리한 뒤 다음 사건 처리. 정리 불명은 실행 차단 |
| a3·b2 수용 | 02: Telegram과 독립된 GHA 검사 결과 생산·수집 | 같은 SHA의 경고→무통지 정상은 해소. 결과 누락·부분 조회 실패는 해소 아님 |
| a1·b1 수용 | 04: 고정 검사 코드·의존성과 후보 데이터의 루트 분리 | 기준 정상·후보 위반 및 후보 helper/정책 약화 대조군에서 위반 검출 |
| a4 보류 | 05: 실제 관찰 시작 전 평가 종료 기준 확정 | 최소 사건 수·범위·수동 대응 비교·성공/실패/평가 부족을 관찰 전에 기록 |

2차 리뷰 a1도 수용했다. 04번 원장 어댑터는 후보 rows와 기준 revision의 budget을 별도 입력으로
구성한다. 후보 budget 변경은 별도 제안/평가로 표시하며 고정 검사에 사용하지 않는다. 후보 행과
budget을 함께 높이는 반례, 기준 budget 누락/중복/기형의 대조군을 추가했다. 사용자는 이 보완에
대한 추가 리뷰 1회(plan r3)를 요청했다.

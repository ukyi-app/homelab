# 비대화형 Codex 운영 진단과 수정 패치 초안

Status: needs-info
Updated: 2026-09-12

## 확정한 요구

| 항목 | 사용자 결정 |
|---|---|
| 목적·대상 | 장애 알림 뒤 원인 파악. 처음부터 모든 장애 알림을 대상(Q1·Q5). |
| 산출·권한 | 진단과 수정 패치 초안까지(Q2). Telegram 보고와 GitHub PR로 전달(Q7). homelab 전체 파일의 초안을 허용(Q8·Q12). 전용 fork에서 homelab Draft PR로 게시(Q11). |
| 장애 범위·실행 | NUC 생존 장애에 한정(Q3). NUC 전용 계정·systemd에서 실행(Q6). |
| AI·인증 | 비대화형 `codex exec`로 파일럿을 먼저 진행. Polyrelay는 후속 연결. 기존 ChatGPT/Codex 구독만 사용(Q4·추가 선택). |
| 예산·증거 | 중복을 묶고 동시 1건·하루 20건(Q9). 상태·메트릭·이벤트와 민감값을 제거한 선별 로그를 Codex에 전달(Q10). |

아직 구현 합의 전이다. 이 파일은 설계 인터뷰 기록이며 배포 명세가 아니다.
근거와 대안은 [아키텍처 검토](research.md)에 둔다. 라이브 상태는 이번 조사에서 조회하지 않았다.

## 결정 트리

```text
첫 목적: 장애 알림 뒤 원인 파악 [확정]
├─ 산출: 진단 + 수정 패치 초안 [확정]
│  ├─ 모든 장애 알림 [확정] → AM·ArgoCD·CNPG·GHA·외부 deadman 접점 조사 완료
│  ├─ homelab 전체 파일 [확정] → 전용 fork→Draft PR [확정]
│  ├─ Telegram 보고 + GitHub PR [확정] → 공개 가능한 정보 / Draft 검토 경로
│  └─ 불확실할 때 보류 / 검증 및 승격 기준 [다음 라운드]
├─ 장애 범위: NUC 생존 전제 [확정]
│  └─ NUC 전용 계정·systemd [확정] → 증거 수집 경로 / 알림 수신 방식
└─ 인증과 과금: 기존 구독만 [확정]
   ├─ 중복 묶음·동시 1건·하루 20건 [확정]
   ├─ 상태·메트릭·이벤트+선별 로그의 전송 [확정]
   └─ codex exec 파일럿 우선 · Polyrelay 후속 연결 [확정]
```

추천은 추천으로만 기록한다. 미응답을 승인이나 기본값 확정으로 해석하지 않는다.

## 현재 단계

Q1~Q12와 추가 개발 순서 선택을 받았다. **AIOps 파일럿은 `codex exec`로 먼저 진행하고
Polyrelay는 후속 연결**한다. [Polyrelay 평가](deferred-polyrelay.md)의 선행 개발을
파일럿에 포함하지 않는다. [최종 설계안](design.md)과 [구현 작업 목록](implementation.md)을
준비했다. 남은 단계는 전체 공유 이해 확인(Q13)이며 구현 착수 전이다.

## 요구의 해석과 설계 제안

사용자는 첫 대상도 **모든 장애 알림**을 원한다. ArgoCD 비수렴만으로 제한하는 추천은 채택하지
않았다. 따라서 배포·파드·호스트·스토리지·인증·감사 등 통지 생산자를 열거해 수집 범위의 누락을
확인한다. 모든 종류를 진단하는 것과 모든 종류에서 수정 패치를 만들 수 있는 것은 구별한다.
원인이 외부 장애이거나 관측이 부족하면 수정안을 억지로 만들지 않고 보류 근거를 보고한다.

Q7로 GitHub PR 발행과 Telegram 보고가 산출 범위에 들어왔다. Q2의 초안 경계를 유지하려면
Draft PR을 만들고 자동 머지를 활성화하지 않는 구현이 적합하다. 원본 증거는 로컬에 두고 public
PR에는 검토에 필요한 비민감 근거만 쓰는 것을 추천한다. 새 PR 발행 자격은 Codex 프로세스와
분리한다. 실제 게시·실행기 설치는 설계 합의와 구체 구현 뒤 수행한다.

Q8로 수정 경로를 배포 설정·관측성 규칙에 한정하는 추천은 채택하지 않았다.
필요한 파일은 모두 초안을 만들 수 있어야 한다. 현재 same-repo Draft PR도 CI와 IaC plan을
실행하므로 초안의 파일 범위와 운영 자격을 가진 코드 실행을 구별해야 한다. Q11에서
**전용 fork에서 homelab으로 Draft PR을 올리는 경로**를 선택했다. same-repo CI 승인 경계
개편안은 채택하지 않았다. Q12로 첫 파일럿의 수정 대상은 **homelab 전체 파일**로 확정했다.
원인이 외부 앱 소스에 있으면 근거와 외부 수정 필요를 보고한다. 해당 앱 레포에 수정 PR을
발행하거나 배포 설정을 억지로 바꿔 대신 해결한 것으로 처리하지 않는다.

Q9의 하루 20건은 사건 처리 상한이며 토큰 사용량을 보장하는 값이 아니다. 재시도·재진단의
계상 단위, 1건 시간 제한, 보류 우선순위는 구체 계약으로 제시한다. 초과 사건은 대기와 통지로
처리한다. Q10의 로그 허용은 무제한 로그 전송이 아니라 사건 관련 구간을 선별하고 민감값을
제거한 뒤 제공하는 범위다. 원본 로그와 시크릿은 public PR에 첨부하지 않는다.

## 최종 설계에서 구체화한 계약

| 계약 | 반드시 정할 내용 |
|---|---|
| 사건 입력 | 대상 알림, 묶음·재통지·resolved 처리, 중복 기준, 만료와 재수집 |
| 증거 | 읽기 권한, 수집 시간창, 생략·실패 표시, 외부 전송 가능한 데이터, 지식 문서의 현행성 |
| 수정 초안 | 고정 revision, 허용 경로와 변경 종류, 검증 격리, 패치 없음이 정상인 경우 |
| 실행 | 위치, 인증, 시간·자원·호출 예산, 재시도, 실패 알림, 중지 방법 |
| 수용 | 정답 근거가 있는 평가 사례, 보류 정확성, 운영자 시간 절감, 초안 수용 기준 |

## 문서화 규칙

합의된 산출의 의미는 루트 `CONTEXT.md`의 **운영 수정 초안**에 기록했다.
진단·초안까지라는 권한 경계는 `docs/decisions/0008-aiops-diagnostic-drafts.md`에 남긴다.
fork PR의 실행 경계는 `docs/decisions/0009-aiops-fork-pr-boundary.md`에 남긴다.
아직 정하지 않은 세부 구현 추천은 accepted ADR에 포함하지 않는다.

## 구현 순서 제안

1. **사건·증거 계약**: 통지 생산자 전체의 사건 형식을 맞추고 정상·관측 누락·실패를 구별하는
   fixture를 만든다. 사건 영속 기록과 기존 통지가 서로 막히지 않게 한다.
2. **NUC 실행기**: 전용 계정·systemd, 사건 큐, 구독 로그인 유지, 동시 1건·일일 20건,
   중단·재시작 처리를 구현한다. 먼저 모의 Codex로 실행 수명과 권한 경계를 검증한다.
3. **진단과 게시**: 고정 revision과 증거에서 실제 Codex가 분석·초안을 만들고 검증기가
   결과를 확인한다. 선택한 PR 경로와 Telegram을 별도 게시 역할로 연결한다.
4. **전체 통지 수용 시험**: 모든 생산자의 실패·경고 사례를 끝까지 통과시킨 뒤 실제 알림을
   처리하는 파일럿을 시작한다. 일부 알림 종류만 연결한 상태를 전체 범위 완료로 부르지 않는다.

## 기본값으로 제안할 실행 계약

아래 값은 아직 수용 전인 구현 제안이다. 최종 설계 확인에서 묶어서 검토한다.

| 항목 | 제안 |
|---|---|
| 처리 단위 | 사건 1건의 진단과 패치 생성까지를 한 실행으로 계상. 재시도·재진단도 일일 슬롯을 소비. 날짜는 Asia/Seoul. |
| 시간·큐 | Codex 단계 합계 10분. 수집·검증·게시와 전체 처리 시도에도 유한 상한 적용(design.md 5절). critical 우선과 장기 대기 처리. |
| 보류 | 관측 부족·시크릿이 필요한 수정·코드 변경으로 해결되지 않는 원인은 근거와 다음 확인을 보고. 패치 없음도 정상 산출. |
| 공개 산출 | Draft PR에 변경 이유·검증·한계, Telegram에 요약·PR 링크. 원본 증거는 로컬 보관. |
| 반복 방지 | 동일 사건의 반복 알림은 기존 기록에 합침. AIOps가 낸 통지/CI 실패는 기존 사건에 연결하며 무한 자기 진단을 금지. |

상한은 진단과 패치 생성을 합친 Codex 단계 총 10분이다. 로그 기본 창·크기·보존 기간과
최소 평가 사례는 [설계의 실행·증거·수용 계약](design.md)에 구체화했다. 숫자로만 비용이나
정확성을 보장하지 않는다. 조정 가능한 초기값까지 포함한 Q13 확인을 기다린다.

2026-09-12 적대적 리뷰 판정에서 단계별 외부 종료 감독, Telegram과 독립된 GHA 정상 결과,
고정 검사 코드와 후보 입력 분리를 수용했다. 관찰 종료·효과 기준은 실제 관찰 시작 전까지
보류하며 구현 착수의 추가 차단으로 삼지 않는다. 세부 계약과 수용 시험은 design.md와 티켓에 있다.

# AIOps 구현 검토 기록

검토 기준은 `6fdb739...394c7a8`, 첫 보완은 `1c22b98`이다. 승인한 10개 티켓의 코드 구현을
규약과 스펙으로 나누어 독립 검토했다. 두 번째 검토에서 확인한 GHA 진행 문제도 수정 후 같은 반례로 재검증했다.

## Standards

| 지적 | 판정 | 반영·검증 |
|---|---|---|
| P2: 정책·ADR 변경 경고가 PR에서 잘림 | 수용·해소 | 고정 경고·변경 경로·다음 확인을 별도로 게시. PR API 대역에서 네 번째 ADR 확인 항목까지 검증 |
| P3 판단: 사건·게시 상태의 일반 문자열 | 수용·해소 | 사건 실행·PR·Telegram·게시 상태를 각각 타입으로 한정. 외부 실패 코드는 reason으로 보존 |
| 추가 P2: root 사전 점검이 만든 DB/WAL의 그룹 쓰기 누락 | 수용·해소 | SQLite 기본 생성 모드가 0644임을 확인. WAL 생성 전에 0660으로 고정하고 수신 역할 그룹 수정 |
| 추가 P2: 기본 kubectl 경로 불일치 | 수용·해소 | k3s 경로 `/usr/local/bin/kubectl`로 수정하고 설치 전 실행 가능 여부 확인 |

규칙 근거: `CONTRIBUTING.md`, `AGENTS.md`, ADR-0008의 정책·ADR 충돌 표시.
최종 재검토에서 확인된 미해결 P1/P2는 0건이다. 상태 타입 지적은 문서 위반이 아닌 설계 판단이었다.

## Spec

| 지적 | 판정 | 반영·검증 |
|---|---|---|
| P1: JSON 로그의 짧은 자격값 유출·지원 형식 누락 | 수용·해소 | JSONL 필드 선택·따옴표 자격값 제거·깨진 구조/바이너리 생략. 공개 collect 경로의 반례로 검증 |
| P1: auth/capacity 회복 대기·실행 전 실패 재시도 누락 | 수용·해소 | 영속 대기와 명시적 resume, 시작 실패 1회 재입장과 예산 계상. 프로세스 경계 회귀 통과 |
| P2: 최근 GHA 30건 밖 이력 누락과 관측 0건의 성공 표시 | 수용·해소 | 최신 100건·고정 기간 분할·영속 페이지/대기 목록·attempt 대조. 두 번째 페이지 실패 후 재개와 같은 run의 정상 복귀 검증 |
| 재검토 P2: 최신 누락 run이 과거 조회 예산을 소진 | 수용·해소 | 최신 30초/과거 45초 분리. 가상 시간 대역에서 첫 실행 pending=[102], 다음 프로세스 pending=[]로 진행 |

승인 스펙의 근거는 지원하지 않는 원문 생략, auth/quota 회복 대기, 확인된 실행 전 실패 한 번 재시도,
누락·부분 관측 실패의 가시성이다. 미요청 범위 확장은 발견하지 않았다.
최종 재현 검증에서 확인된 미해결 P1/P2는 0건이다.

## 검증 범위

- 초기 구현의 전체 Bats 3,415개 통과. 리뷰 수정 후 AIOps 회귀 43개 통과.
- `just verify`, TypeScript, actionlint, 변경 셸의 shellcheck 통과.
- 12개 고정 사례·5개 생산자 계열을 모의 엔진으로 통과시켰다. 실제 모델 진단 품질은 미검증이다.
- 설치 설정·역할·systemd·producer 배선 생성물과 비활성 `commission` 경로를 준비했다.
- 실제 NUC 역할/cgroup·전용 구독 로그인·생산자 도달·fork PR/Telegram·14일 관찰은 미수행이다.

## 운영 수용

`docs/aiops.md`의 순서로 sudo가 필요한 모의 호스트 검증, 전용 역할 설치/인증,
격리·fork 설정 검증, 사건별 commissioning, 12개 실제 진단 수용을 수행한다.
관찰 최소 표본·범위·수동 대응 비교·종료 기준은 관찰 시작 전에 확정한다.
실제 수용이 끝나기 전에 readiness 증거를 true로 채우거나 파일럿 효과를 입증했다고 기록하지 않는다.

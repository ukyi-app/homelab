# TS 코드 표면 adapter는 유보한다

CONTEXT.md 「가드 adapter」는 두 adapter가 있어야 seam이 실재한다고 규정하고, 「코드 표면」 판정은
지금 셸 가드 6개에만 있다. `tools/check-alert-rules.ts`·`tools/check-workflow-readiness.ts` 등 TS 가드도
자기 코드-줄 판정을 갖고 있어, 2026-08 아키텍처 리뷰가 TS 대응물을 함께 세울 것을 물었다. **유보한다.**

지금 만들면 두 구현을 영구히 동기화할 비용을 지불하겠다는 약속이 되고, 표면 어휘가 두 언어에서 정합해야
한다. 그 비용에 값하는 실증은 아직 없다 — TS 쪽 표면 결함은 오늘 한 건 관측됐을 뿐이다
(`tools/check-alert-rules.ts:490`의 `//` 주석이 `<<EOF`를 인용해 605줄이 은닉된 것. 이것은 셸 가드가
TS 파일을 스캔하다 생긴 것이라 TS adapter가 아니라 셸 검출기의 표면 종류 게이트로 닫힌다).

셸 쪽 코드 표면 커널 자체도 같은 리뷰에서 기각됐다 — 넓힌 홑따옴표 delimiter 축을 처리하는 유일한 기전이
이 레포의 `` <<'AWK' `` 관용구를 미종료로 만든다(실측 67파일 / 264건). 대신 형태 대조 게이트로
관용구 동일성만 강제한다. adapter가 하나도 커널 형태가 아닌 상태에서 두 번째를 세울 이유가 없다.

재개 조건: **세 번째 TS 가드가 같은 표면 결함을 낼 때**.
그 전까지 아키텍처 리뷰는 이 후보를 재제안하지 않는다.

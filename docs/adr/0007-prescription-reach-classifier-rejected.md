# 처방 도달을 하나의 정적 가드로 판정하지 않는다

2026-08 아키텍처 리뷰가 후보 8건을 올렸는데 **전건이 같은 클래스**였다 — 한 자리에서 실증된
처방이 형제 표면에 닿지 않은 자리. 그 관찰은 자연스럽게 다음 제안을 부른다: "그럼 처방 도달
자체를 가드로 만들자. 어떤 처방이 어느 표면에 닿아야 하는지 판정하는 가드 하나면 18건을
한꺼번에 닫는다."

**기각한다.** 그 가드는 세 가지를 열거해야 하고, 셋 다 열거할 수 없다.

| 열거해야 하는 것 | 왜 열거할 수 없는가 |
|---|---|
| **처방의 목록** | 처방은 코드가 아니라 **판단**이다. `-eq 1` 전환은 리터럴이지만, "바닥값과 양성 대조를 한 쌍으로"는 형태이고, "판정을 `git add` 앞에 인라인한다"는 순서이며, "README가 계산 가능한 것을 주장하지 않는다"는 삭제다. 이 넷을 한 스키마로 표현하려면 스키마가 곧 처방의 재서술이 된다 |
| **인접 표면의 집합** | 「처방 도달」의 진단 3조건 중 ②가 "형제 표면이 같은 실패에 노출됐다"인데, **형제 관계는 도메인 지식이다.** `test_host-ports.bats`와 `alertmanager-render-e2e.sh`가 형제인 것은 둘 다 publish 컨테이너를 띄우기 때문이지 파일명·디렉토리·확장자 어느 것으로도 파생되지 않는다 |
| **비대칭의 정당한 근거** | 조건 ③이 "그 비대칭에 근거가 적혀 있지 않다"인데, 근거는 산문이다. 이 캠페인에서 정당한 비대칭이 실제로 나왔다 — `git grep`은 양성 대조만 요구한다(pathspec 무매치도 rc 1이라 파일시스템 바닥값이 닫을 것이 없다). 기계가 이것을 "누락"과 가르려면 그 산문을 읽어야 한다 |

셋 중 하나라도 열거하면 **열거 밖이 안전이 된다.** 이 레포가 함정 원장에 이미 이름 붙인
클래스(「열거 붕괴 → vacuous green」)이고, ADR-0002가 같은 자리에서 다섯 번 죽었다.

## 이 캠페인이 그 대신 한 것

18건을 **각각 다른 처방으로** 닫았다. 공통성은 가드가 아니라 **어휘**로 남겼다 —
`CONTEXT.md` 「처방 도달」(진단 3조건 포함). 다음 리뷰는 이 클래스를 이름으로 인식하되,
후보마다 처방을 새로 판단한다.

그리고 처방이 **재유입되지 않는 축에 한해서는** 가드를 세웠다. 그것이 가능했던 이유는 그
축들이 **리터럴 형태**라 열거가 필요 없기 때문이다:

- `[ABS]` 래칫 — `run grep <경로>` + `-ne 0` 철자, 그리고 재귀·루프 자리에 바닥값과 양성 대조를
  접속사로 요구하는 형태
- `[QV]` hard-zero — `grep -qv` 관용구
- `verify-traps` 방향 ④ — SSOT 헤드라인 ↔ AGENTS 인덱스의 완전 일치

셋 다 "이 형태가 소스에 있는가"이지 "이 처방이 저 표면에 닿았는가"가 아니다. 그 구별이 이 ADR의
전부다.

## 재개할 때 쓸 비회귀 기준선

기각했지만 **측정은 유효하다.** 18건이 각각 어떤 모양으로 착지했는지가 재개 시점의 출발선이다.
가상의 분류 가드는 이 표의 「처방 모양」 열을 스키마로 표현할 수 있어야 한다.

| # | 티켓 | 처방 모양 | 신설 module |
|---|---|---|---|
| 01–04 | 부재 단언 전환 (4 레인) | 리터럴 철자 + setup 비공허 단언 | 0 |
| 05 | `[ABS]`·`[QV]` 래칫 가드 | 기존 가드에 클래스 추가 + venue 배선 | 0 |
| 06 | 컨테이너 기동 프리미티브 | **함수 추출**(6불변식) — seam은 readiness 앞 | **1** |
| 07 | `versions.env` 3-값 리더 | 새 실행 파일 + 정적 어휘 가드 | 1(스크립트) |
| 08 | `scripts/README.md` 축소 | **삭제** + 판정 재설계(venue 어휘 합집합) | 0 |
| 09 | `verify-traps` 4방향 | 방향 추가 + fail-closed 전환 + argc 원자화 | 0 |
| 10 | 앱 표면 값 경계 | 타입 좁히기(함수→값) + 가드를 손 열거→행 순회 | 0 |
| 11 | 철거 absence 극성 | **행위 변경**(두 ref 관측) | 0 |
| 12 | APPS 편집 라우팅 | 커널에 export 2개 추가 + 콜사이트 이관 | 0 |
| 13 | ops 재핀 표기 통일 | 정규식 제자리 협소화 + 집합 대조 게이트 | 0 |
| 14 | `audit-orphans` 스캔 신호 | 콜사이트 안에서 커널 판정 경유 + 페이로드 신호 | 0 |
| 15 | 스테이징 완전성 | **판정을 5곳에 각 언어로 인라인**(공유 module 아님) | 0 |
| 16 | `--ensure-cmd` 정정 | usage를 파서 표에서 파생 + `cli.ts` 수렴 | 0 |
| 17 | `tf-r2-init` 파생 | **입력 제거**(등식을 표현 불가능하게) + 실행 픽스처 증인 | 0 |
| 18 | `pr-sweeper` 증인 | 파생 우주 교체(`LANES` → 무장 초크포인트 전수 스캔) | 0 |

**신설 module은 18건 중 2건뿐이다.** 적대 검증이 나머지 후보 4개를 deletion test로 죽였고
(`tests/lib/absent.sh` · `scripts/assert-staged-complete.sh` · `sealedFileFor` export ·
`scanFields` 커널 함수), 그 넷의 대체 처방이 전부 "이미 실증된 형제 처방을 제자리에서 가져와라"였다.
분류 가드가 이 표를 재현하려면 "처방"의 정의가 함수 추출·타입 좁히기·행위 변경·입력 제거·삭제·
인라인·파생 우주 교체를 모두 포함해야 한다.

## 이 캠페인이 실측한 라이브 결함 (그 가드가 잡았어야 할 것들)

재개 시 후보 가드의 감도는 이 목록으로 잰다. 전부 **게이트가 막겠다고 선언한 회귀를 실제로는
못 막던** 자리이고, 전부 뮤테이션으로 재현됐다.

- `test_auth.bats` — 상시 write-capable PAT을 되살려도 4·5번 단언이 `ok`
- `test_ensure-bump-pr.bats` — 도구를 리네임하면 안전 증인 98곳 중 25건이 살아남고, 하필 그것이
  force-push 가드들(W11c 페이지네이션 · W75/W77 ref 불일치 · W80 3자 합의)
- `test_host-ports.bats` — `grep -qvF` 6곳 중 5곳이 항진. 그중 둘이 ADR-0005 seam 축의 유일한 증인
- `test_ops-repin.bats` — "every"라 선언하고 부분 미갱신에 눈이 멀었다(5사이트 중 1곳·2사이트 중 1곳)
- `scripts/verify-traps.sh` — SSOT가 사라지면 rc 0으로 "양방향 일치 OK"를 출력
- `test_destroy-node.bats` — 파괴 프리미티브의 sudo 누출 검사가 대상 리네임에 홀로 초록
- `test_sops-roundtrip.bats` — 대상 없이 "평문이 살아남지 않았다"가 참(황금률 2 방향)
- `tools/lib/mutation.ts` — 철거 수렴에서 경로 오타가 "철거 완료"와 같은 값
- `test_pr-sweeper.bats` — selector 정규식을 통째로 지워도 9/9 초록

## 기각이 남긴 부채

- **잔액 5곳** — `[ABS]` 래칫이 `ABS_BASELINE=5`로 시작한다(`test_app-token-sha-ssot` 2 ·
  `test_sealed-secrets-restore` 2 · `test_seal-secret` 1). 그 자리들은 증인이 **산문으로는 실재**하고
  형태만 없다(예: 양성 대조가 스텁 팩토리 안에 있어 존재 기반 판정이 같은 스코프로 못 본다).
  래칫이라 늘지는 않지만 0으로 미는 것은 별도 작업이다.
- **`[ABS]`의 증인 판정은 존재 기반이다** — 피연산자로 연결하지 않는다. 셸에서 피연산자 동일성은
  정적으로 결정 불가능하고, 결정하는 척하면 그 연결이 조용히 어긋나 가드 자신이 vacuous green이
  된다. 대가는 같은 스코프에 동종 증인이 하나 더 남으면 한쪽 삭제가 안 보인다는 것이다.
- **프로그램 rc 부재 단언에는 처방이 없다** — `run bash <스크립트>` + `-ne 0` 형태는 rc가 그
  프로그램의 규약이라 철자로 못 닫는다. 그 자리의 축은 **피연산자 실재 증인**이고,
  `.scratch/followups.md`에 3건이 등재돼 있다.
- **검출기는 `@test` 밖 줄을 부분적으로만 본다** — 05번이 0열 함수 본문까지 넓혔지만, `@test`가
  아예 없는 seam 파일(`test_helper.bash` 류)은 도메인에 있으면서 판정 밖이다.

**재개 조건**: **인접 표면 집합이 열거 가능한 도메인이 나타날 때.** 즉 형제 관계가 파일명 규약이나
원장으로 이미 선언되어 있어 열거가 **파생값**인 경우다 — 그런 도메인에서는 열거 밖을 안전으로
읽는 문제가 원리적으로 생기지 않는다. 예: 「가드 adapter」처럼 두 구현이 같은 규약을 만족해야
한다고 CONTEXT.md가 선언한 축, 또는 `policy/` 원장이 소비자를 이미 열거하는 축.
그 전까지 아키텍처 리뷰는 이 후보를 재제안하지 않는다.
